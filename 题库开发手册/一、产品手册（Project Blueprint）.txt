## 0. 文档使用规则

### 0.1 信息优先级

从高到低依次为：

1. 本产品手册中标记为“已确认”的规则；
2. 《三、交流文档》中已经形成明确结论、但尚待整理进手册的决议；
3. 《二、变更日志》中记录的已完成改动；
4. 当前代码与测试所反映的实现现状；
5. `docs/`、产品诊断报告、交接报告和历史聊天记录。

旧资料可作为证据和建议来源，但不能自动覆盖本手册。

### 0.2 状态定义

- **已确认**：产品负责人已经确认，后续开发必须遵守。
- **已实现**：当前开发版本已有对应代码和基本测试，但不代表生产环境已经可用。
- **部分实现**：只有部分链路可用，不能对外宣称完整能力。
- **规划中**：方向被记录，但尚未进入稳定交付。
- **待确认**：存在口径冲突或关键信息不足，相关开发应暂停或保持现状。
- **待整改**：当前代码与本手册目标不一致，需进入后续变更计划。

### 0.3 标准变更流程

1. 开始工作前，阅读本手册、《二、变更日志》的最新记录和《三、交流文档》的既有决议。
2. 先在本手册中补充或修改产品规则，再改代码。
3. 没有明确口径时，先搜索交流文档；仍无结论，则在交流文档末尾发起问题并暂停争议部分。
4. 完成代码与验证后，立即在变更日志记录修改人、时间、原因、影响范围、验证结果和遗留问题。
5. 聊天中的口头结论只有写入本手册或交流文档后，才成为跨 Agent 的长期口径。

## 1. 产品定义

### 1.1 产品定位【已确认】

薯考是一款面向广东普通专升本汉语言文学考生的微信题库、练习记录与复习工具。产品围绕指定科目和教材组织题目，以可信答案、教材依据和人工审核为内容底座，帮助用户找到练习范围、记录学习进度，并逐步判断下一步该练什么。

产品的核心属性是“软件工具”，不是学历教育、培训班、学校、教师授课平台或考试结果保证服务。

推荐的一句话说明：

> 把知识点拆开练，把进度看得见。

内部长期价值方向：

> 不只记录错题，还要帮助用户找到下一步该练什么，并用后续题目验证是否真正掌握。

### 1.2 核心用户【已确认】

- 广东普通专升本汉语言文学相关考试的学习者；
- 主要处于按教材学习、建立知识框架、开始刷题或阶段复习的人群；
- 需要确认复习范围、检验掌握程度、安排后续练习并保存学习资产的人群。

### 1.3 用户要完成的核心任务【已确认】

1. 确认要学哪些科目、教材、章节和知识内容；
2. 通过题目检验自己是否真正掌握；
3. 在做错或证据不足后，知道下一步该练什么；
4. 通过同类、变式或延迟复测获得新的掌握证据；
5. 保存错题、收藏、知识卡、笔记、题包和练习历史。

### 1.4 产品非目标【已确认】

- 不以全国性“海量题库”或题目数量最多为首期竞争目标；
- 不用少量题宣称“AI 精准诊断真实水平”或预测考试分数；
- 不承诺保过、押题命中、提分幅度、证书或考试通过率；
- 不允许 AI 自动修改、覆盖或发布权威答案；
- 不把同一题复制成多份实体数据来实现不同题池或目录；
- 首期不建设私信、关注、好友等社交关系；
- 首期不提供实时教师授课、学籍管理或培训证书。

## 2. 首期范围与当前阶段

### 2.1 首期考试范围【已确认】

对外产品与范围统一表述为：

> 薯考 · 汉语言文学题库 · 广东专升本

产品不建立按年份复制的考试项目，也不在项目名称、题库名称或长期入口中保留年度标识。真题、模拟卷、题目来源、考纲版本和当期活动仍应保留其真实年份作为元数据。当前代码和页面中的“2026”项目标识属于待迁移旧实现，应逐步移除，迁移过程不得复制题目或丢失历史记录。

### 2.2 五科九本教材【已确认】

| 科目 | 教材 |
| --- | --- |

### 2.3 产品组成【已实现】

- 原生微信小程序：用户做题、复习、管理学习资产和账号；
- Node.js API：承载目录、题目、练习、AI、账号、额度和管理接口；
- 网页管理后台：教材、题目、题族、知识档案、AI 巡检和运营管理；
- 本地文件存储与 PostgreSQL 兼容层；
- 教材 PDF、OCR/MinerU 正文和后台检索材料。

### 2.4 当前产品阶段【已确认】

当前是内部开发与样板验证阶段，不是生产稳定版。

- 《现代汉语》是知识树、题族、知识档案与 Agent 巡检的首个样板；
- 用户端已有大量可运行页面，但真实内容规模、正式 AppID、AI 路由、消息提醒和生产数据仍依赖部署配置；
- 学情分析、综合训练、难度、题族和知识档案均为部分实现，不能对外包装成成熟诊断闭环；
- 真实微信支付、完整 OCR 录题和全量九本教材知识档案尚未上线。

## 3. 核心产品原则

### 3.1 工具属性优先【已确认】

推荐用语：

- 题库、练习、题目包、练习规划；
- 知识卡、复习工具、进度分析；
- 视频讲解、章节要点与题目示范；
- AI 辅助解析、AI 辅助评分。

在完成专项资质核验前，不使用：

- 系统课、培训班、授课、名师辅导、学费；
- 保过、押题命中、提分保证、报名、结业或证书；
- 暗示与教育考试主管部门存在隶属、合作或授权关系的表述。

已确认的发现页用语：

- Banner：`把知识点拆开练，把进度看得见`
- 商品：`汉语言文学练习规划与题目包`
- 商品说明：`适合碎片时间查看`
- 学习方式：`视频讲解（章节要点与题目示范）`
- 规划入口：`学习营地`

### 3.2 可信内容优先【已确认】

- 教材 PDF 或可核验原始资料是最终证据，不允许 AI 编造原文、页码、来源或官方意见；
- OCR、目录、知识档案、规则和向量检索均是辅助层，不能反向篡改原始证据；
- AI 生成内容必须标明来源和不确定性；
- 题目、答案、教材引用、题族和规则只有经过人工确认后才能进入权威链路或智能推荐。

### 3.3 一个事实只保留一份权威数据【已确认】

- 综合题池是跨科目、教材、知识点和难度的虚拟查询，不复制题目；
- 公共题库、精选题库和平台自营题库是收录或权限关系，不复制题目核心条目；
- 一道题属于多个题族时仍是同一个题目 ID；
- 目录、题族详情和搜索可以从不同角度引用同一题，但不得生成内容副本。

### 3.4 AI 建议、人工裁决【已确认】

AI 可以识别、提取、生成候选、检索相似案例和提示风险，但没有最终发布权。教材目录、题目、答案、知识树、知识档案、题族、规则和公开内容的正式状态必须由人工确认。

### 3.5 承认证据不足【已确认】

无法确定时必须保留“无法确定、证据不足、待归组、待人工审核”等状态。不得为了完成流程强行选择知识点、创建题族、给出精确诊断或伪造进度。

## 4. 权威领域模型

### 4.1 总关系【已确认】

```text
教材 PDF（原始证据）
  -> OCR / MinerU 正文知识库（有版本的检索投影）
  -> 教材知识树（知识在哪里）
  -> 知识档案（概念是什么、边界和关系是什么）

题目（题干、材料、选项、答案）
  -> 题目知识焦点及其显式角色 + 作答的最小充分知识集（本题直接问什么或跨知识范围落在哪里、作答要懂什么）
  -> 主题族 + 关联题族（具体怎样考、后续怎样练）
  -> 用户作答、错题、复习和学情证据
```

必须长期使用的统一表述：

> 知识树管位置，知识档案管概念，题目知识焦点通过 `core / scope_anchor` 角色分别表达“本题直接问什么”或“跨知识题主要落在哪个范围”，最小充分知识集只管“作答必须懂什么”，题族判别焦点与成员归属管“按什么稳定规则训练、后续怎样练”。

### 4.2 教材原始资料层【已确认】

- 教材 PDF、试卷原文件和明确来源的答案是不可静默改写的原始资料；
- 原文件、文件版本、来源和权利状态必须保留；
- 教材 PDF 与连续 OCR 正文主要用于后台证据检索，不向用户提供可替代原教材的整本下载。

### 4.3 OCR/正文知识库【已确认】

- OCR/MinerU 正文是原始资料的可检索投影，不等于最终事实；
- 必须保留 PDF 页码、教材印刷页码、目录位置、片段 ID、内容版本和原文；
- OCR 错误可以修复，但修复必须留痕，不能反向改变原始文件。

### 4.4 教材知识树【已确认】

教材知识树回答“知识在教材哪里”。典型层级为：

```text
科目 > 教材 > 章 > 节 > 知识点 > 知识小点
```

规则：

- 目录可以继续向下细分，不受课本一级小标题限制；
- 支持人工新增、改名、移动、排序和删除未被引用的节点；
- 一个目录节点可以包含多个概念；同一概念可以在多个目录位置出现；
- 知识树是导航骨架，不是概念真理，也不是题族；
- 左侧目录应支持折叠；长按移动属于目标交互，移动后必须校验题族和题目引用。

### 4.5 教材知识档案【已确认】

知识档案回答“一个规范概念是什么、边界在哪里、与其他概念有什么关系、教材证据是什么”。

档案至少包含：

- 规范名称和别名；
- 定义；
- 纳入边界和排除边界；
- 可核验事实声明；
- 每条声明对应的片段 ID、原文、PDF 页码和印刷页码；
- 多个教材出现位置及角色；
- 与其他知识档案的关系；
- 教材、目录和正文版本；
- 核验状态、人工审核人和版本记录。

档案状态原则：

- 编译 Agent 只能生成草稿；
- 核验 Agent 只能给核验意见；
- 只有满足证据覆盖、边界、关系与人工确认门槛的 `active` 档案，才能作为稳定语义边界；
- `evidence_verified`、`boundary_verified` 等中间状态仍是待确认材料，不能覆盖教材正文；
- Agent 4 只提交档案增量，不直接修改正式档案，也不负责从头扫描整本教材。

#### 4.5.1 题族、题目与案例关联【已确认】

知识档案不保存题目、题族、确认案例、反例或人工纠错的正文副本，也不在档案正文版本中维护不断变化的反向列表。题族仍由题族数据管理，确认案例和纠错仍由 Agent 4 经验数据管理。

需要人工指定正例、反例或其他关联时，使用独立的版本化关联记录，至少包含：

- 档案 ID；
- 目标类型：题族、题目、确认案例、反例或人工纠错；
- 目标 ID 和目标基线版本；
- 关系角色、确认状态、来源；
- 确认人、确认时间、失效状态和失效原因。

知识档案页面和 Agent 输入通过聚合查询生成“相关题族与案例”视图。目标版本变化后，关联记录应进入待复核，不得把旧正文复制回档案以维持展示。

题族的名称、判别焦点、覆盖知识、范围锚点、教材证据锚点、考查动作、题族边界、成员贡献和题族集归属均由题族领域数据维护，不写进知识档案正文。知识档案只维护概念事实层及其审核版本；题族和题族集变化后，通过实时聚合更新档案页，不推进档案正文版本。

#### 4.5.2 档案状态消费契约【已确认】

正式归类、正式推荐和用户侧能力只能使用 `active` 档案。各 Agent 的读取边界如下：

| 角色 | 允许读取的档案内容 |
| --- | --- |
| Agent 1 | 只读取 `active` 档案的规范名称和别名，用于术语标准化；不得读取完整边界并据此覆盖独立特征提取。 |
| Agent 2 | 读取 `active` 档案的名称、边界摘要、关系和目录位置，用于候选排序。 |
| Agent 3 | 正式分类只使用 `active` 档案；可以获知待核档案存在，但不得将待核内容当作已确认依据。 |
| Agent 4 | 可读取 `active` 和待核版本，用于向现有档案或草稿提交增量，但不能激活档案。 |
| 编译 Agent | 读取教材原文、上一 `active` 版本和现有草稿，生成新草稿。 |
| 核验 Agent | 读取草稿、上一 `active` 版本和原始教材证据，只给出核验意见。 |
| 用户推荐链路 | 只能读取 `active` 档案。 |

RAG 负责提供教材原文事实；知识档案提供规范名称、边界、关系、目录位置和稳定引用，不能替代原文证据。

#### 4.5.3 教材依赖与精确失效【已确认】

档案必须保存教材文件版本和哈希、OCR/正文知识库版本、目录版本，以及每条引用片段的 ID、标准化文本哈希、页码位置和所支撑的事实声明。

失效顺序：

1. OCR 重建但引用文字和页码映射未变时，只更新引用映射，不让档案失效；
2. 某个引用片段内容变化时，先让依赖它的事实声明待复核；
3. 核心定义或边界声明失效时，对应档案版本进入待复核；
4. 目录移动但概念内容未变时，只复核教材位置；
5. 无法证明未受影响时，才扩大为整章或整本待复核。

#### 4.5.4 正式概念关系【已确认】

正式关系类型如下：

| 关系 | 语义与方向 |
| --- | --- |
| `is_a` | 种属关系，有向；反向界面可展示为上位/下位。 |
| `part_of` | 整体与组成关系，有向；不得与种属关系混用。 |
| `prerequisite_for` | 前置知识关系，有向。 |
| `supplements` | 补充说明关系，有向；不自动进入作答的最小充分知识集。 |
| `contrasts_with` | 对比关系，双向语义。 |
| `confusable_with` | 易混关系，双向语义。 |

`is_a`、`part_of` 和 `prerequisite_for` 必须执行有向环校验。系统只保存一个规范方向，反向名称由界面和查询派生，不重复维护两条事实。

“同概念候选”和“不确定”是审核状态，不是正式概念关系。确认同义后应合并为同一档案或登记别名；确认前不得把两个概念当作同一概念供正式分类使用。

正式关系只能指向实际存在的知识档案 ID。目录归属由教材出现位置表达，不得用目录节点 ID、目录名称、书目 ID、占位符或其他非档案实体伪造概念关系。

#### 4.5.5 已激活档案的修改与停用【已确认】

已发布的 `active` 版本与待审核的新草稿版本并行保存，不直接覆盖：

1. 排版、标点和不改变含义的明显错别字，经过轻量审核后发布补丁版本，不触发完整复核；
2. 别名、目录位置和检索词变化，进行局部核验，上一 `active` 版本可继续使用；
3. 教材引用、原文或页码变化，重新进行证据核验；上一版本证据仍有效时可以继续使用；
4. 定义、纳入边界、排除边界或概念关系变化，进行完整独立核验，并让依赖该版本的分类建议进入待复核。

若修改原因是上一 `active` 版本内容错误、证据失效或可能持续造成错误归类，必须立即暂停旧版本。新版本激活前，正式链路回退到教材原文检索或“证据不足”，不得为了保持可用而继续消费已知错误档案。

#### 4.5.6 知识档案人工审核界面【已确认】

知识档案的普通审核界面面向教研审核员，不得直接把事实声明、教材位置和概念关系的原始 JSON 作为主要编辑方式。

- 规范名称和别名属于基本信息，不作为重复的大段审核内容展示；
- 定义、每条纳入边界、每条排除边界、每条事实声明和每条概念关系分别构成独立审核单元；
- 每个审核单元支持待审核、通过、驳回和证据不足状态，并允许单独修改与填写审核说明；
- 审核单元应直接展示或展开其教材原文、片段 ID、PDF 页码和印刷页码，不要求审核员在 JSON 中寻找证据；
- 每个“通过”的审核单元必须绑定至少一份当前档案中的有效教材证据；单元内容或证据绑定变化后，旧结论、审核人和审核时间自动失效并回到待审核；
- 页面应通过聚合查询展示可能受该概念影响的题族，题族正文不复制进档案；
- 教材出现位置默认以紧凑来源摘要展示，只有需要检查来源角色时再展开；
- 原始 JSON 只允许放在默认关闭的高级只读区域，用于排障和完整数据核对；
- 档案激活前，定义、边界、事实声明和正式概念关系必须完成逐项人工审核；存在驳回、证据不足或未完成项时不得激活。
- 知识档案页左侧教材目录右侧的数量只表示该目录范围对应的知识档案数，不显示题目数；父目录包含其全部下级目录，通过多个教材位置落在同一范围的同一档案只计一次；“全部知识点”显示当前教材的档案总数。题库页继续按原口径显示题目数量。

#### 4.5.7 题族覆盖、缺口与风险投影【已确认】

知识档案页动态聚合以下只读结果，不把结果写回档案正文：

- **对应题族**：题族覆盖知识与档案概念节点相交，且教材证据锚点能够提供来源依据的已确认题族；题族范围锚点只作组织定位，不得单独证明知识覆盖；待审核和已驳回题族不计入正式覆盖；
- **题族集**：由对应题族当前所在题族集及其上级题族集实时反查，题族集只表达组织关系，不伪装成概念关系；
- **已覆盖考法**：按已确认题族的考查动作聚合，并列出对应题族；题目数按题目 ID 去重；
- **题库缺口**：当前档案没有任何已确认题族，或已有题族没有可识别的统一考查动作时，标记为待补题族/考法；
- **审核风险**：题族尚未确认、没有成员、只有一道成员而样本不足、纳入或排除边界缺失、考查动作缺失或与成员动作不一致，题族判别焦点/覆盖知识缺失，范围锚点过高，或者覆盖知识尚未得到已激活且证据完整的档案支持时，进入风险列表。单题题族的“待扩充/样本不足”是质量风险，不改变其人工确认结果。

题族、题族集和题目数量均按稳定 ID 去重。同一道题属于多个题族时，在档案覆盖总量和题族集统计中只计算一次。动态投影用于教研审核、候选题族补齐、题目完善和 AI 补充答案的检索依据；正式 Agent 判断仍只能把 `active` 档案正文当作概念裁判标准，待审核投影不能成为正式事实。

### 4.6 题目与题目版本【已确认】

题目是最小内容和训练单元。判断题目归类时必须把题干、共享材料、全部选项、结构化正确答案、来源答案、参考答案、解析、题目来源、教材和版本作为整体。

题目修改必须保留版本。历史作答绑定当时的题目版本，不得被后续编辑静默改变。

#### 4.6.1 题目知识标注与考试标签【已确认】

题目内容与知识归类在存储、接口和页面中必须保留来源分层，不得合并成一个无来源的“当前值”：

1. **题目正式字段**：当前 `question.version` 对应的题干、材料、选项、正式答案、解析、来源及其他题目事实；
2. **`confirmed` 知识指纹**：经过人工确认并绑定题目版本的唯一题目知识焦点、显式 `core / scope_anchor` 角色与作答最小充分知识集，是正式知识归类；历史字段或界面中的“核心考查知识”按角色缺省为 `core` 的题目知识焦点兼容读取；
3. **AI `suggested` 候选**：Agent 提出的知识节点、理由和置信信息，只供审核比较；未经人工确认不得提升为 `confirmed`，也不得代替正式字段或正式知识指纹参与目录、训练和冻结。

题目正式字段与 `confirmed` 知识指纹可以在待复核期间暂时出现冲突，系统必须同时保留并显示双方原值、来源、状态和题目版本，明确提示人工处理；不得通过接口拼装、页面兜底或题族定义覆盖来制造表面一致。没有 `confirmed` 指纹时应明确显示“知识指纹待确认”，不能拿 AI `suggested` 候选、题族判别焦点、题族覆盖知识或教材目录节点冒充正式指纹。

管理端题目编辑页是人工查看和修改题目正式知识指纹的主要入口。题族页只负责只读比对题目正式指纹、题族指纹和单独标识的 AI 候选，不在题族确认表单内直接编辑题目指纹；其他正式审核入口如需修正题目知识，只能调用与题目编辑相同的正式业务命令、版本与审计协议，不能各自直接写入知识结构。

- 题目自身的知识点标注用于教研解释、Agent 特征判断、选项诊断和动态关系计算，不直接决定用户端题库目录中的展示位置；
- 用户端目录位置由题目的唯一主题族及该题族的范围锚点投影决定，教材证据锚点、关联题族和题目知识标签不得额外生成同题副本；
- 题族成员列表、成员详情和题族内题目编辑入口必须读取并展示成员题目当前版本的真实正式字段与 `confirmed` 知识指纹，不得用所在题族的判别焦点、覆盖知识、范围/证据锚点或 AI 候选替换、覆盖或兜底；
- 题目考试标签使用多选字段 `examTags`，稳定值至少包括 `insert`（插本）和 `graduate`（考研），同一道题可以同时拥有两项；
- 迁移期继续兼容旧单值 `examTrack`，但管理端保存后应收敛为 `examTags`，不得因兼容逻辑丢失第二个标签。

#### 4.6.2 重复题合并与下架【已确认】

重复题合并用于把多个事实相同的题目实体收敛为一个规范题，不用于把相似题、同类题或变式题合并。每次合并必须明确一个 `canonicalQuestionId` 和一个或多个 `mergedSourceQuestionId`，并遵守以下规则：

- 规范题继续作为唯一可用于新练习、题库选择和后续维护的题目实体；源题改为离线合并状态，保存 `mergedIntoQuestionId`，不得物理删除；
- 合并源题是终态归档，不是普通“已下架”题目：不得再次编辑、恢复、归组或经普通批量删除销毁；它默认退出题库、未成族、题族选择、AI 完善和巡检等活动工作区，只能在合并审计、版本历史或原题稳定 ID 下只读查看，并可跳转到规范题；
- 普通永久删除还必须拒绝删除任何仍被合并源题指向的规范题，避免留下悬空映射。若合并判断错误，应使用独立、原子且可审计的撤销合并流程，不得用“恢复”冒充撤销；
- 合并映射必须可从源题追溯规范题，也能从规范题反查全部源题；不得形成自指、循环或多级合并链，已作为源题合并的题目不能继续充当新的规范题；
- 合并默认只处理重复实体与关系，不自动拼接、覆盖或折中题干、选项、答案、解析、来源和教材证据；确需吸收源题字段时，必须另行执行有版本记录的题目编辑，并继续遵守答案分层与人工审核规则；
- 面向未来使用的活跃关系迁移到规范题，包括题族成员、知识归属以及已登记支持合并的试卷、题包、审核队列等关系；系统发现尚未纳入合并协议的活跃引用时必须阻断提交，不得留下悬空或双写关系；
- 合并完成后，离线设备迟到上传的活跃复习状态与收藏必须按稳定映射收敛到规范题；历史作答、历史复习和评分记录仍保留原题 ID，不因同步而改写历史；
- 规范题已经存在相同关系时必须幂等合并，不创建重复关系；关联题族可以去重后并入，主题族仍只能有一个。源题与规范题存在不同主题族时，必须由人工明确保留哪一个，未裁决不得提交；
- 历史作答、历史巡检、旧审核记录、操作日志及其当时的题目版本继续绑定原题 ID，不得改写成规范题 ID；需要继续查看时可以通过合并映射跳转到规范题，但展示中必须保留原题和原版本身份；
- 源题离线、全部活跃关系迁移、关系去重、题族审核失效、合并映射和操作日志必须作为一次原子提交完成；任何一步失败时，源题状态、规范题状态和全部关系都保持提交前状态；
- 合并属于危险操作。管理端必须展示规范题、源题、将迁移的关系和冲突裁决结果并进行二次确认，服务端仍须独立执行权限、版本、范围、引用完整性与循环校验。

### 4.7 答案分层与发布口径【已确认】

答案来源必须分层保存，不得混写：

1. 来源答案：原始材料确实附带的答案；没有则保持为空，不得假定考试机构提供；
2. 教材答案与证据：教材明确结论、原文和结构化得分点；
3. 平台核验答案：平台基于来源材料、教材证据和人工教研形成并审核的发布答案；
4. 经审核的社区共识答案；
5. 明确标记的 AI 补充答案。

考试机构通常不提供答案，平台不得因此把自拟或人工核验答案标记为“官方答案”。用户侧用于判分的答案必须明确展示为来源答案、教材答案或平台核验答案。AI 答案不得覆盖、折中或修改来源答案、教材证据或平台核验答案；存在冲突时，应停止相关发布、判分或归类采纳，交由人工裁决。

“官方题库、官方答案”不用于表示平台自营、平台收录或平台人工核验内容。若材料确有明确发布主体，应在来源字段中如实标注具体机构和文件，不把来源关系扩展为平台获得官方授权。

### 4.8 题目知识焦点【已确认】

题目正式知识指纹继续只保存一个题目知识焦点，但必须同时保存该焦点在本题中的显式角色。金标答案知识使用 `answerKnowledge.coreKnowledgeRole`，正式题目指纹使用同义字段 `primaryNodeRole`；允许值只有 `core` 与 `scope_anchor`。旧记录缺少角色时一律按 `core` 读取，不能根据题目内容、批次版本或目录层级自动猜测为 `scope_anchor`。

- **`core`**：该节点最直接回答“这道题在考什么”，属于作答的最小充分知识集；主题题族覆盖知识必须包含它，主题成员贡献也必须承载它。普通单知识题和能够稳定选出唯一直接考点的题继续使用该角色；
- **`scope_anchor`**：只用于表达跨知识题主要落在哪个教材或教研范围，帮助管理、检索和人工理解；它不是作答知识事实，不自动进入最小充分知识集，不参与主题族与作答必需关联族的联合覆盖，也不要求主题题族覆盖或主题成员贡献承载。`scope_anchor` 只能由人工在确认跨知识范围时显式选择，不能因它是多个节点的父级、共同祖先或当前目录而自动采用。

`core` 应尽量落到能够稳定解释本题目标的具体知识节点，不得为了迁就现有题族，把“单纯词”之类的具体焦点上提到“词的结构类型”等父目录。`scope_anchor` 可以使用较高层范围节点，但它只描述组织范围，不得伪装成作答所需知识。无论哪种角色，题目知识焦点都不是主题族、题族判别焦点、题族范围锚点或用户目录投影事实。

### 4.9 作答的最小充分知识集【已确认】

作答的最小充分知识集是可靠推出或判定答案时必须实际调用的最小知识节点集合。

当 `coreKnowledgeRole / primaryNodeRole=core` 时，题目知识焦点必须属于该集合；当角色为 `scope_anchor` 时，焦点不得因其范围身份被自动加入，集合只保留逐项通过删除检验的作答知识。角色切换属于正式知识指纹变化，必须经过人工确认和题目版本化流程。

1. 题目必须同时调用 A 与 B 才能作答时，两者都入选；
2. 选项判断题只有在验证正确项或可靠排除干扰项时确实需要某项知识，才纳入；
3. 题目直接需要 B，而 B 的理解或应用天然包含前置 A，且 B 已足够作答时，只标 B；
4. 不得因题干、材料或选项出现某个名词就覆盖式全收；
5. 对每个候选执行删除检验：移除后仍能稳定作答，则该知识不是作答必需知识；
6. 前置背景、相关但不参与作答的知识只用于解释，不进入题族归属和复习推送。

题族覆盖多个知识，不代表每道成员题都必须调用全部覆盖知识。不得因现有题族横跨兄弟节点，反向扩写题目的最小充分知识集。选项知识、题族覆盖知识和本题作答必需知识必须分别保存；只有通过本题删除检验的知识才进入本题最小充分知识集。

“主知识点/副知识点”是废弃口径，不再用于表达题族归属。

### 4.10 题族【已确认，待整改】

题族回答“这个知识具体怎样被考”。同一最小知识点下可以存在多个考查方向不同的题族。

题族采用六组定义事实：

1. **题族名称**：面向审核和训练的可读名称；名称本身不是唯一性依据；
2. **题族判别焦点**：描述成员题共同使用的稳定判别规则或能力，例如“依据语素构成区分单纯词与合成词”；它是题族语义中心，不是教材父目录；
3. **题族覆盖知识**：该稳定判别任务允许覆盖的明确知识节点集合；它可以大于任一道成员题的最小充分知识集，但不得因加入单题自动扩张；
4. **教材定位**：包括唯一题族范围锚点和多个教材证据锚点。范围锚点用于组织、检索和用户目录投影；证据锚点用于指向实际教材位置，两者不得再由一个字段混合承担；
5. **考查动作**：`assessmentAction`，描述识别、判断、辨析、分析、计算、应用等实际作答动作；
6. **纳入与排除边界**：`inclusionBoundary` 与 `exclusionBoundary`，明确哪些题属于该族、哪些相似题不属于该族；普通人工确认时允许暂空并在后续补充。

统一判断公式：

```text
题族 = 相同判别焦点
     × 相同覆盖知识范围
     × 相同考查动作
     × 相同辨析边界（纳入边界 + 排除边界）
```

该公式描述题族语义完善后的判断目标，不等同于普通人工确认的表单必填规则。审核员已经能依据成员题、判别焦点、覆盖知识、教材定位和考查动作作出可靠判断时，可以在纳入边界或排除边界暂空的情况下确认题族；系统必须保留空值并标记“题族边界待补充”，不得杜撰边界，也不得因此阻断确认。边界补充后参与后续相似题判断、动态关系和审核风险计算；补充内容与既有成员冲突时，题族应重新进入待审核。

同一题族的判断应核对当前已有的六组事实、题干/材料/全部选项、正确项和干扰项的实际辨析机制，以及与现有已确认成员的相似性。仅名称、教材路径、共同父节点、关键词、`focusKey` 或题干相似都不足以证明同族。同一判别规则下的互斥兄弟类别可以组成一个题族；只是偶然在一道题中共同出现、但判断规则不同的知识必须拆成多个题族。

题族范围锚点原则上由覆盖知识的最近共同父节点生成候选，再由人工确认。它只回答“这一族放在哪个教材范围”，不得进入题目最小充分知识集、成员贡献知识或联合覆盖，也不得因为某节点是另一节点的父级就自动判定题目与题族兼容。共同父节点过高、跨越不相干分支或无法表达稳定训练范围时，应保留多个证据锚点并提示拆族，不得自动扩大题族边界。

当前实现中的 `coreKnowledgeNodeId`、`requiredKnowledgeNodeIds`、`knowledgeNodeId` 和 `textbookAnchorNodeIds` 属于旧题族定义兼容字段。在新结构落地前不得把旧值静默改名或重新解释为判别焦点、覆盖知识、范围锚点和成员贡献；正式迁移必须带定义协议版本、预演、人工复核和审计记录。已冻结金标继续按其原协议和原字节解释，不能用 DEC-039 回写 V1/V2 历史事实；后续金标与回放上下文必须显式记录新的题族定义和成员贡献协议版本。

题族定义与成员题目的正式知识指纹是两层独立事实。题族成员审核必须以只读方式并列展示“题目知识焦点、焦点角色与最小充分知识集”“题族判别焦点、覆盖知识与范围锚点”“本题在该题族中的贡献知识”，并按该成员的主题族或关联题族角色执行 4.11 的兼容校验；AI `suggested` 候选另行标记为未确认，不参与正式一致性结论。题目知识焦点不等于题族范围锚点不构成错误；`scope_anchor` 未被主题题族覆盖或贡献承载也不构成错误。真正的不兼容是本题贡献知识不在题族覆盖范围、判别焦点/考查动作/边界不适用，或联合覆盖失败。

规则：

- 可以先创建空题族骨架，再加入题目；
- 可以批量选择多道题创建新题族或加入已有题族；
- 同一教材、同一知识位置且规范化名称一致的题族视为同一个可见语义题族；不同历史 ID 或生成来源不得造成重复展示、重复新建或重复成员关系；
- 同一道题重复归入同一语义题族时必须幂等合并；历史重复题族应归并到一个规范题族，旧 ID 只作为兼容别名解析，不复制题目；
- 题目编辑页及归组操作中的题族选择器必须支持按题族名称和知识路径搜索，并只展示去重后的可选题族；
- “归入题族”只新增目标题族关系并保留已有关系；“移动”只替换本次勾选的来源题族关系，可移动到已有题族，也可新建题族后移动；
- 批量移动只允许选择同一个真实来源题族中的成员。来源与目标不得相同；整批必须在一次题族 Store 写入中全部成功或全部不写入，不能由前端串联“先加入、后移除”；
- 移动后来源题族即使变为空集也继续保留，不自动删除；来源与目标题族的定义事实未变化时继续保持原定义状态，只将本次迁移涉及的成员关系标为待审核；
- 题族判别焦点、覆盖知识、范围锚点和教材证据锚点均在各自选择或编辑组件中维护；判别焦点与范围锚点各自唯一，覆盖知识和证据锚点允许多选，不再用一个“核心知识”字段同时表达语义中心和目录位置；
- 题族目录主锚点变化不再使用独立“整体移动题族”入口，而是随普通确认/保存一次提交。提交前提示目录变化和成员不变；取消时不得写入；成功后管理端定位到新锚点；
- 范围锚点变更必须在一次题族 Store 写入中同步目录路径、层级、排序、证据锚点、题族定义、成员和最终审核状态。写入前校验节点、覆盖知识范围、题族集允许范围和目标目录重复；失败时全部不写入；成功后推进全部成员的题族归属修订号，使引用旧归类的巡检建议失效；
- 题族可以删除；删除题族不得删除题目。独立 `/relocate` 服务端接口只作兼容保留，不作为日常管理端入口；
- 未确认题族不得进入智能复习；已确认题族中只有归属关系已确认且题目仍有效的成员可以进入用户目录、智能复习、专项训练和正式统计；
- 题族的 `confirmed` 只表达题族判别焦点、覆盖知识、教材定位、考查动作与边界已经人工裁决，不再连带表示此后新增或变化的每一条成员关系都已经确认；成员归属和贡献知识使用独立状态表达；
- 确认或保存题族只提交题族判别焦点、覆盖知识、教材定位、题族状态和成员关系；即使成员题目的正式指纹与题族定义不兼容，也不得由题族确认动作修改、补齐或新建题目指纹，不得推进题目版本；
- 普通人工确认至少需要 1 道成员题，并且必须且只能保留 1 道原型题。只有 1 道成员的题族可以确认，确认后派生标记为“单题待扩充/样本不足”；该标记是质量与供给提示，不是新的审核状态，也不得把题族降回待审核；
- 0 道成员的空题族只能作为待审核骨架保存，不得确认。不得复制同一道题、强行合并相近题族或放宽题族语义边界来凑足成员数；
- 普通人工确认题族时，纳入边界和排除边界均为选填；缺少任一边界只形成待完善的教研质量风险，不改变确认结果；
- 题目内容、正式答案或知识指纹发生实质变化时，只将该题在各题族中的成员归属与贡献知识精确标为待审核；题族定义事实未变化时，题族自身继续保持已确认。来源、标签、难度、排版等不影响题族适配的字段变化不得触发题族或成员归属失效；
- 新增、移除、移动成员，或切换该题的主题族/关联题族，只影响本次变化涉及的成员关系；不得仅因成员集合或成员数量变化把来源与目标题族整体退回待审核；
- 只有题族判别焦点、覆盖知识、范围/证据锚点、考查动作或纳入/排除边界等定义事实发生实质变化，才让整个题族退回待审核并重新校验全部成员；仅修改某一成员的贡献知识、成员角色或题目内容时只精确失效该成员关系；名称、说明、排序和题族集层级等不改变题族语义的展示/组织字段不得触发整族失效；
- 删除最后一个已确认有效成员，或唯一原型题的归属失效时，题族定义可以继续保留已确认，但派生为“暂无可用成员/原型待处理”，暂停进入用户训练，直至至少一条成员归属重新确认；该派生状态不是新的题族审核状态；
- 归入、移出、移动题族或切换主题族/关联题族只改变题族成员关系和训练归属，不自动修改题目正式字段、`confirmed` 知识指纹或题目版本；确需修正正式知识时必须进入题目正式编辑与审核流程形成新版本；
- 原型题、同类题、变式题以及基础、拔高、迁移/拓展层级属于题族内部训练关系；延迟复测是训练调度角色，不应复制题目。

当 Agent 找不到符合题族定义的现有题族时，只能生成“候选新题族草稿”，不得直接创建正式题族。草稿必须同时包含名称、判别焦点、覆盖知识、范围锚点、教材证据锚点、考查动作、纳入边界和排除边界，并提出本题的成员贡献知识；只有人工确认草稿并确认题目归入后，系统才创建正式题族关系。人工驳回或暂不确定时，题目继续保持待归组，草稿保留为可审计建议而不是空题族事实。

### 4.11 主题族、关联题族与待归组【已确认，待整改】

- 一道题可以属于多个题族，但只能有一个主题族；
- 主题族是该题最主要的训练与错因归属；用户端只依据主题族的题族范围锚点投影，教材证据锚点、关联题族和题目知识标签不额外投影；
- 关联题族分为“作答必需”和“普通关联”两类。作答必需关联题族表示可靠作答确实必须调用的其他考查方向，其逐成员贡献知识参与最小充分知识联合覆盖和专项训练；普通关联只记录相似、易混、前置或教研参考关系，不参与知识覆盖、专项训练或盲测题族命中计分；
- 选项里出现过某知识，不等于自动成为关联题族；
- 没有准确题族时进入待归组；可以提出候选新题族草稿，但不得为了完成流程让 AI 直接创建正式题族。

题目指纹与题族定义的兼容判断按关系角色区分。每条主题族或作答必需关联题族成员关系必须保存或在人工审核中明确确认“本题贡献知识”，它表示该题族实际承载了本题最小充分知识集中的哪些节点；题族整体覆盖知识不得直接替代逐成员贡献。

- **基础门禁**：题目知识焦点角色必须显式为 `core` 或 `scope_anchor`；旧记录缺省为 `core`。`core` 必须属于题目 `confirmed` 最小充分知识集，`scope_anchor` 不自动属于该集合。主题成员和作答必需关联成员的贡献知识仍必须非空，并同时属于题目最小充分知识集与题族覆盖知识。父子、祖先、同章或共同范围锚点关系均不能替代这一交集校验；
- **主题族兼容**：当题目焦点角色为 `core` 时，题目知识焦点必须被主题族覆盖知识明确包含，且主题成员贡献必须包含该焦点；当角色为 `scope_anchor` 时，不要求主题族覆盖或主题成员贡献承载该锚点，但主题成员贡献仍须为非空的作答知识子集。两种角色下都不要求题目知识焦点等于题族范围锚点，也不要求某一道题调用题族覆盖的全部知识；题族判别焦点、考查动作和纳入/排除边界仍必须适用于本题；
- **作答必需关联题族兼容**：成员贡献知识必须是题目最小充分知识集的非空子集，并落在该题族覆盖范围内；该考查方向必须确实参与本题作答并通过删除检验；
- **联合覆盖门禁**：主题成员与全部作答必需关联成员的贡献知识并集，必须与题目最小充分知识集按规范节点集合等价。遗漏任何节点时阻断保存；任何成员贡献题目知识集之外的节点时也阻断保存；删除某个必需关联关系后仍能完成覆盖时只提示冗余风险，由人工结合考查动作和删除检验裁决；
- **普通关联题族兼容**：不保存用于联合覆盖的贡献知识，只记录相似、易混、前置或教研参考关系；不得借普通关联补足门禁，也不得进入专项训练推送或完整题族命中计分；
- **候选新题族兼容**：无匹配题可以由“候选主题题族成员贡献 + 现有作答必需关联题族成员贡献”联合覆盖整题；只禁止填写现有主题题族 ID，不得为了新建主题族而清空已经成立的关联题族；
- 没有 `confirmed` 指纹时只能标记兼容性待确认；AI `suggested` 候选可以提示可能冲突，但不能据此确认题族关系、成员贡献或改写任何正式事实。

典型例：题目“下面的词属于单纯词的有”可以把“单纯词”作为题目知识焦点；“单纯词与合成词识别”题族可把二者作为覆盖知识，把“词的结构类型”作为范围锚点，并以“依据语素构成区分单纯词与合成词”作为判别焦点。该题是否还要把“合成词”纳入最小充分知识集，必须依据正式答案、教材证据和删除检验判断，不能因为题族覆盖二者就自动补入。

跨知识例：“花蝴蝶儿”当前可以把“词汇单位”暂作为 `scope_anchor` 候选，但它不得因此进入最小充分知识集或要求主题题族承载。现有六项最小充分知识仍混有范围节点、祖先节点和可能重复表达同一命题的节点，必须由人工依据正式答案、教材证据与删除检验逐项精简；本决议不自动删除、替换或确认其中任何节点。

成员关系使用独立审核状态：

- `confirmed`：人工已经确认该题适合以当前角色归入该题族，可以参与正式目录、训练、统计、案例检索和盲测上下文；
- `pending_fit`：新增、迁移，或因题目内容、答案、正式知识指纹、成员贡献知识及主副归属变化而需要重新核对；只在管理后台显示，不进入任何用户侧正式消费；
- 旧数据没有成员审核状态时，已确认题族中的既有成员按 `confirmed` 迁移读取，待审核或已驳回题族中的成员按 `pending_fit` 读取；再次人工保存后必须显式落库。

题族定义状态与成员归属状态必须分别显示和筛选。已确认题族包含待审核成员时显示“已确认 · N 个成员待审”，不能把它混入“题族定义待审核”；批量导入后只需审核新增题目的成员归属，不得要求重新确认已经稳定的题族定义及旧成员。

当同一判别焦点、覆盖知识范围和考查动作在多个独立题目中稳定重复时，可以建立一个跨知识或跨兄弟类别的综合题族；偶发的跨知识组合优先使用多个作答必需题族联合归属，不得为每一道综合题机械新建只含一题的组合题族。

移动成员时只迁移用户本次勾选的来源关系，其他题族关系保持不变。来源关系是主题族时，目标关系接替为主题族；来源关系是关联题族时，目标仍是关联题族。若目标题族已经包含该题，则合并为一条关系并保持唯一主题族约束，不复制题目或成员关系。

同一题在多个题族中被引用时仍是一个题目 ID。题库主目录不应生成多份题目副本；关联题族详情可以显示其关联身份。

### 4.12 题族集【已确认】

题族集回答“多个题族如何在更高一级训练主题下组织”。它是绑定教材知识树节点的管理与导航容器，可以包含题族和下级题族集，但不直接包含题目，也不替代知识节点、知识档案或题族。

规则：

- 题族集可以先创建为空集，之后再加入题族或下级题族集；
- 题族集支持逐层嵌套，用于表达“发音特征 > 元音发音特征 / 辅音发音特征”等跨下级知识位置的训练主题；父题族集必须位于能够覆盖其成员的同一本教材知识范围内；
- 题族集采用严格树结构：一个题族最多只有一个直属题族集，一个下级题族集也最多只有一个直属上级题族集；未归集题族可以继续直接位于教材知识节点下；
- 题族集只保存组织关系，不复制题目，不改变题族的教材知识归属、主题族/关联题族关系、审核状态或题目版本；
- 新建、编辑和迁入内容时必须支持按题族集名称、题族名称和知识路径搜索；已经归入其他题族集的内容只能通过“移动”迁入；
- 上级题族集经下级题族集间接覆盖的题族和更深层题族集均视为已经归入，不得再次作为上级集的直属成员候选；如需拍平层级，必须先在原下级集中明确移出，再重新加入，不得用一次“移动”跨层拉出；
- 同一次新建或迁入不得同时选择祖先集与其后代集，也不得同时选择下级题族集及其内部题族；页面应自动保留最高层选择并清理重叠项，服务端仍须在写入前整批校验；
- “移动”必须原子替换直属题族集关系，先完成范围、唯一直属关系和循环校验，再一次性写入；编辑题族集时，名称、教材位置、上级集与本次成员迁入也必须作为一个整体提交；任一步失败时元数据、版本号、原关系和目标关系均不得变化；
- 题族集不得包含自身或自己的任一上级，移动后也不得形成循环；
- 解散没有下级题族集的题族集时，只解除组织关系，保留其中题族及其全部题目；仍有下级题族集时禁止解散，必须先移动或解散下级集；
- 题族集成员管理使用“当前内容 / 可归入内容”标签页，默认打开“可归入内容”；两个列表复用完整成员区高度，搜索、计数、勾选和移出能力不得因切换而丢失；
- 列表和详情分别使用“个题族集、个题族、道题”作为统计单位；题目数按题目 ID 去重，不能把同题在多个题族中的引用重复计数。

#### 4.12.1 动态题族关系【已确认】

题族集只维护稳定、明确且需要人工组织的训练主题树。易混、前置、相似、跨章节、共同案例等多维关系，不全部手工塞入题族集层级；系统优先依据题族判别焦点、覆盖知识、范围/证据锚点、考查动作、边界和已确认案例动态计算，并展示计算依据与置信状态。动态关系不改变题族集直属关系，也不能未经人工确认反向改写题族定义事实。

### 4.13 题目难度【已确认】

- 用户看到一至五星；
- 系统内部保留 1-100 连续难度分和置信度；
- 考频、内容冷门度、认知深度、题型/作答负担和实测难度分开记录；
- 考频表示考试价值，不直接等于难度；
- 样本不足时显示暂定或低置信，不得伪造精确程度；
- 刷题范围支持按难度筛选。

## 5. Agent 协作与人工审核

### 5.1 Agent 1：特征提取【已确认】

输入必须包含题干、材料、全部选项、来源答案或平台核验答案，以及题目元数据。Agent 1 独立提取题干核心关键词、每个选项涉及的候选知识及角色、解题实际依赖的知识与调用顺序、主次判断、跨题族概率和调用深度，只产出结构化特征，不改正式数据。

- 题目知识焦点先判断角色：能够稳定回答“题干归根到底在问什么”时使用 `core`；跨知识题只能确定主要组织范围、而该范围本身不是作答知识时才使用 `scope_anchor`。两种角色都不能按题干和选项出现的名词覆盖式标注；
- 对“以下哪个说法正确/错误”等题干不预设单一知识的题，必须逐项判断。一般提高正确项知识的权重、降低单个干扰项权重；若多个干扰项共同来自同一知识且辨析它们构成主要解题机制，该共同知识可以成为主判断，正确项知识反而成为次要判断；
- 每项知识最终是否进入作答必需知识，仍须通过最小充分知识集的删除检验；仅出现、仅相关或只是前置背景的知识不进入正式归属。
- Agent 1 对每个选择项必须先给出知识关系候选，而不是为了满足字段完整性强制生成知识节点。候选关系使用 `question_only`、`option_specific` 或 `undetermined`；只有 `option_specific` 才输出可单独归因的选项知识，且必须说明该知识为何参与验证或排除该项。该候选继续属于 AI 层，不能绕过 DEC-033 的人工首次判断隔离。

### 5.2 Agent 2：分层归类【已确认】

Agent 2 根据 Agent 1 特征，结合知识树、`active` 知识档案边界、已确认题族和人工确认/改判案例，从上到下逐层检索候选。教研规则库只作为冷启动与例外补丁，不作为长期主引擎。

- 每层最多提供 5 个直接子节点；
- 保留“当前层已足够、涉及多个、无法确定、候选均不合适、上一层可能选错”等出口；
- 五个候选均不正确时必须选择“候选均不合适”或“无法确定”，不得为了完成流程强行归类；该题随后交由 Agent 3 进行整树重新检索；
- 不得越级、创造节点或直接修改题目；
- 案例足够后，主匹配逐步切换为已确认案例和向量召回，规则库降级为冲突提示与兜底。

同一导航层遇到非法 JSON、越界候选、选择了未提供的“多个”或其他合同错误时，最多允许一次针对具体错误的约束纠正。纠正请求必须携带原错误码、上次输出和本层允许的候选；第二次仍非法时终止该题的 Agent 2 合同流程，不得继续重试或伪造合法结果。`multiple_not_offered` 的纠正必须选取能直接推出答案的唯一核心路径，其他确属独立作答依赖的知识写入 `auxiliaryGap`；相似题族案例不得压过更具体的教材规则。

### 5.3 Agent 3：教材与题族核验【已确认】

Agent 3 回到教材原文独立校核：教材是否存在该知识、当前档案边界是否有充分证据、题目是否属于候选知识和题族、题族是否已有真实成员，以及与成员的相似性。教材有知识但尚无可用档案时提出“待归档”；有合适题族时提出加入建议；没有合适题族时生成候选新题族草稿；仍不足以判断时进入待归组。必须查看真实题目及全部选项，只提建议，不自动合并、建族或落库。

“独立核对”意味着 Agent 3 可以重新检索整棵知识树，不受 Agent 2 前五候选、终点节点或局部父子/兄弟节点范围限制。Agent 2 路径只作为待核验建议，不得成为 Agent 3 的硬约束。Agent 3 改判时必须给出新节点、教材证据和否定原路径的理由。

候选新题族草稿必须一次给全名称、题族判别焦点、题族覆盖知识、题族范围锚点、教材证据锚点、考查动作、纳入边界和排除边界，并列出本题作为主题或作答必需成员时的贡献知识、教材证据及相似题比较。审核员可以逐字段修改、确认创建并归入、驳回或保持待定；只有“人工确认创建并归入”才产生正式题族和成员关系。

Agent 3 的主请求、独立备用请求和唯一合同纠正请求，都必须在容量限制内优先保留每个终点知识节点可取得的直接教材片段；语义检索噪声不得挤掉该证据。任务审计需分别记录三类请求、父子关系、错误码、所提供证据片段和候选范围，不能只保留最终输出。

Agent 3 同一次核验对非法 JSON、越界候选或题族合同冲突最多进行一次定向纠正。纠正请求必须携带原错误码、精简后的上次裁决、允许的知识节点、证据和题族；供应商备用路由不等同于增加合同纠正次数。`join_existing` 只能选择 `confirmed` 题族，并按 4.11 区分角色校验：题族判别焦点、考查动作和边界必须适用于本题；题目焦点为 `core` 时主题族必须覆盖且主题成员贡献必须承载该焦点，题目焦点为 `scope_anchor` 时不做这两项要求；主题成员和作答必需关联成员都必须给出通过删除检验的非空贡献。主题族与全部作答必需关联题族的成员贡献知识必须联合等价覆盖整题最小充分知识集，`scope_anchor`、普通关联和题族范围锚点均不参与门禁。首次选择不兼容题族后不得再次把它写入对应角色，只能留作普通关联或 `matchedFamilyIds` 供比较。主题族没有兼容现有题族时必须 `create_new`、清空 `primaryFamilyId` 并提交完整草稿，但可以保留成立的关联题族。第二次仍非法时不得伪造成功或形成题族结论；知识裁决如仍可独立验证可以保留供人工查看，但题族必须降为 `unresolved`，整次 Agent 3 合同状态标记失败。

### 5.4 Agent 4：人工结论沉淀【已确认】

Agent 4 先沉淀审核事件，再决定是否形成规则或档案修订建议。每次人工确认或改判都先保存原始事件；同类问题累计至少 3 个独立案例后，才允许生成一条规则草稿或知识档案修订建议，单个案例不得直接泛化为规则。

人工采纳后，Agent 4 应：

- 保存题目特征、关键词、依赖项、最终知识归类和题族归属为确认案例，并进入后续检索/向量素材；
- 人工改判时保存“题目、Agent 2 原建议、人工最终结论、审核员原文理由”，不强行改写为抽象规则；后续相似题检索时把该改判案例标记为高参考权重；
- 与已激活规则冲突时记录规则例外，不自动修改规则；
- 向知识档案提交别名、边界、关系、证据、例外或冲突增量；
- 同一反馈主题优先补充或修订原草稿，必要时才创建新规则；
- 草稿、已启用和已停用规则均允许人工发起删除；删除必须保留操作者、时间、原因和原规则快照，已启用规则删除前明确提示且确认后立即退出后续巡检；
- 规则、档案和候选新题族均不能由 Agent 4 自行批准。

### 5.5 处理方式【已确认】

- 各 Agent 按单题流水处理：上一 Agent 完成一题后立即交给下一 Agent，不等待整批完成；
- 一题达到人工审核条件后立即可审，不等待整个批次；
- 页面进度来自真实任务状态，不得使用装饰性进度；
- 审核员可勾选并采纳具体建议，不局限于整条接受或拒绝；
- 历史记录必须说明属于哪次任务、为何保留、是否过期或被新记录取代。

### 5.6 人工审核顺序【已确认】

1. 先确认题目知识焦点和作答的最小充分知识集；
2. 再确认一个主题族、零到多个关联题族，或选择待归组；
3. 修改 AI 建议时填写调整依据，并以原文保存；
4. 题目版本、知识树、教材正文或题族版本变化后，旧建议应判过期并说明原因；
5. 只有人工采纳后，结果才进入正式知识指纹、题族关系和 Agent 4 经验。

### 5.7 当前实现差距【待整改】

- 候选新题族草稿、旧题族六维字段、用户目录投影和题目考试标签已有首版链路与测试；DEC-039 的 `family_knowledge_v3` 首版链路已实现，题族判别焦点、覆盖知识、范围/证据锚点和逐成员贡献已分层落库，仍需用真实《现代汉语》审核流程验证字段质量、迁移预演和批量操作；
- 四 Agent 的长期持久化学习闭环仍是部分实现，Agent 3 独立结果、Agent 4 三例聚合及档案修订建议尚未全部稳定落库；
- 巡检创建时已保存逐题知识指纹与人工题族成员修订基线；同题人工改归会使旧建议过期。题族名称、状态等更广泛语义变化的精确失效仍待完善；
- 审核弹窗只能从 Agent 提供的知识候选中选择，不能直接从整棵知识树纠正漏选；
- 选项到知识标签及其诊断关系尚未成为稳定数据，不能据此精确判断用户错因；
- 自动成族仍含科目特例，尚未完成“向量匹配为主、规则兜底”的通用引擎。

### 5.8 AI 盲测回放【已确认】

AI 盲测用于判断 Agent 能否在不知道人工结论的情况下重新得到正确归类。被测题先单独保存人工金标准，随后按留一法从 Agent 输入中遮蔽题目现有章节、知识标签、知识指纹、全部题族成员关系、自身确认案例、纠错与反馈记录，以及由本题或本题反馈直接产生的规则。候选题族的名称、判别焦点、覆盖知识、范围/证据锚点、考查动作、边界和其他真实成员可以保留，但样题中不得再次出现被测题自身。

盲测继续保留题干、材料、全部选项、已核验来源答案或平台核验答案、教材正文、知识树、`active` 知识档案、与被测题无关的已批准规则和其他人工确认案例。AI 补充答案和未核验答案不能替代已核验答案。评估至少比较题目知识焦点、作答的最小充分知识集、主题族和作答必需题族集合；普通关联只进入诊断，不进入题族命中率，并记录无法确定、候选新题族与教材证据使用情况。

所有归类场景统一使用 `verified_source_or_platform`。历史持久化提示词中的 `verified_official`、将平台核验结果称为“官方答案”的肯定式说明及其冲突优先级必须在加载时迁移；不得把新禁称条款简单追加在旧肯定条款之后形成自相矛盾的模型指令。

回放必须在独立内存 Store 和随机临时端口运行；巡检结果、AI 任务、操作日志及经验均不得进入正式 `.runtime`。回放只运行 Agent 1 特征提取、Agent 2 分层归类和 Agent 3 教材/题族核验，停在待人工审核状态。Agent 4 只有真实人工确认或改判后才能运行，盲测脚本不得用隐藏金标准冒充人工审核，也不得自动采纳结果。运行前后必须校验正式数据文件哈希未变化，并输出可审计的原始结果和中文报告。

#### 5.8.1 自动补桥与关联题族约束【已确认】

- 由题干或选项关键词、章节邻接、知识关系或科目特例推导出的“桥接知识”，只能作为 `riskHints`、候选知识或人工审核说明返回；不得在 Agent 3 之后追加、替换或改写 `primaryNodeId`、`requiredNodeIds`、`cross_knowledge` 或正式题族关系；
- 作答的最小充分知识集以 Agent 的独立判断和教材证据为准。系统可以指出可能漏掉的概念，但不能把“文本出现过”“属于前置基础”或“与答案相关”直接等同于作答必需；
- 每个“作答必需”关联题族都必须做删除检验：从解题路径中去掉该题族对应的考查能力后，若仍能可靠完成本题核心判断，则不得把它列为作答必需；只在选项、概念基础或章节背景中出现的题族可以保留为普通关联，但不参与知识覆盖和专项训练推送；
- 删除检验约束同时适用于新输出、历史待审核记录、管理端默认勾选和最终采纳。缺少逐项检验、必要性结论、具体检验过程或理由的旧关联建议只能降为普通关联或 `matchedFamilyIds` 供人工比较，不得因历史字段兼容直接进入作答必需归属；
- 自动提示与 Agent 输出必须分别保留来源，报告应能区分模型自主判断和程序补充，不得把程序追加结果伪装成 Agent 的原始结论。

#### 5.8.2 三种盲测模式【已确认】

1. **成熟题族留一**：题族至少有两道独立成员。只隐藏被测题的成员关系与自身经验，保留题族定义和其他成员，用于验证能否归回既有题族；
2. **单题题族整族隐藏**：当题族唯一成员就是被测题时，除隐藏题目关系和经验外，还必须从候选上下文隐藏该题族的名称、定义、锚点、题族集关系、全部别名链和使用旧别名 ID 的历史题族定义。此模式用于验证 Agent 能否提出语义正确的候选新题族草稿；不得把命中由本题建立的既有题族 ID 计为泛化成功；
3. **无匹配建族**：选择人工已确认当前没有合适既有题族的题，并保证候选集中不存在等价题族，用于验证 `candidateFamilyDraft` 的名称、题族判别焦点、题族覆盖知识、范围/证据锚点、考查动作、纳入与排除边界、本题成员贡献知识及证据是否完整、是否避免重复建族。

每轮应覆盖单知识题、跨知识题和选项判断题，并分别报告三种模式的样本数、无法确定率、题目知识焦点准确率、最小充分知识集 F1、主题族准确率、作答必需题族集合 F1、候选建族完整率和错误扩散率。不同模式不得混成一个总命中率掩盖差异。

#### 5.8.3 金标准独立复核【已确认】

人工金标准必须在运行前独立冻结，并记录其教材证据和审核状态。若现有教材节点或证据只能排除部分选项、无法充分说明正确项与相近干扰项的差异，应把样本标记为 `gold_needs_review`，保留回放输出供教研检查，但不得计入模型准确率，也不得为了让模型命中而事后补写金标准、知识节点或题族定义。

即使金标准已经确认，供应商超时、网络失败、任务中断或其他未产生完整 Agent 3 输出的执行失败也不得记作模型分类错误。报告必须单独标记执行失败类型，`countedResult` 保持为空，并明确说明该轮未产生可计分分类结果。

知识树确有缺口时，应按教材原文和知识档案流程另行提出待归档建议。补建“基本音节表、带调音节库存、同音字表”等节点必须先证明它是稳定的教材知识对象，而不是为单道测试题临时增加的答案标签。

#### 5.8.4 连续回放验收门禁【已确认】

归类链路调整后，先在冻结的代码、提示词、模型路由、人工金标准、教材、知识结构和题族数据下完成一次校准回放；校准只验证真实路由、上下文、隔离和评估链路，不计入正式次数。校准通过后，必须使用完全相同条件串行取得连续 5 次可计分通过，方可验收和发布。

每个计数轮次必须同时满足：Agent 1-3 完整结束，Agent 3 合同状态为 `valid` 或唯一纠正后的 `corrected`，`countedResult=true`，题目知识焦点和作答最小充分知识集精确命中，候选新题族草稿完整且语义通过，未返回隐藏金标准题族，泄漏审计通过，正式数据运行前后未变化。五个正式计数报告的运行前哈希还必须彼此一致，并与校准报告一致。

供应商、网络或基础设施失败以及其他 `unassessed` 结果不计准确率、不增加次数，也不作为模型分类失败清零；修复外部故障后原样重跑当前序号。已经形成完整可计分结果但 `countedResult=false` 的真实分类失败会把连续次数清零。门禁期间任何代码、提示词、模型、供应商路由、金标准、教材、知识结构或题族数据变化，也必须清零并重新校准。每轮须保存报告路径、模型路由、错误与纠正次数、任务父子关系和正式数据哈希，不得只记录最终结论。

#### 5.8.6 盲测金标审核与冻结快照【已确认】

“AI 巡检”下设置独立的“盲测金标审核”子页面。批次导入只建立审核草稿，不修改来源答案、平台核验答案、题目知识、题族定义、题族成员关系、巡检记录或 Agent 经验。本轮 Agent 1-3 的选项知识、得分点草稿、知识判断和候选题族必须保留来源标识并与正式基线分开保存，只能作为人工提交首次独立判断后的对比材料；任何按钮都不得自动采纳本轮预测。具体隔离与揭示时点以 DEC-033 为准。

人工审核必须按以下顺序执行：

1. **先审答案、证据与知识**：核对完整题干、材料、全部选项、题目版本、来源答案或平台核验答案、教材证据、唯一题目知识焦点及其 `core / scope_anchor` 角色、作答的最小充分知识集，以及选择题逐选项的角色、知识关系和按需选择的选项知识，或主观题结构化得分点；
2. **再审题族**：只有上一阶段形成终态，才允许审核现有题族判别焦点、覆盖知识、范围/证据锚点、考查动作与边界，预期加入旧题族或新建题族的裁决，主题族、关联题族及逐成员贡献知识，以及单题/无匹配模式需要冻结的候选题族语义；
3. 审核期间发现正式答案或知识本身需要修正时，先进入正式业务编辑流程，完成答案和知识修正并产生新的题目版本；随后刷新金标草稿、使此前题族审核失效，再按新答案与知识重新审核题族。不得在金标审核记录中暗改正式业务数据，也不得保留基于旧知识摘要的题族结论。

DEC-032 的当前实现约束如下：

- 答案/证据/知识审核与题族审核是两次独立的人工提交。第一阶段保存成功后只把题族阶段置为待审核，不得在同一次点击中连续提交两个阶段；题族阶段只有在第一阶段形成终态后才可操作。

答案/知识阶段和题族阶段分别使用同一组三态结果：

- **确认现有值**（`confirmed`）：人工确认当前审核值可以作为该版本金标；

- **存在争议**（`disputed`）：证据、答案、知识边界或题族裁决暂不能唯一确定。该题在冻结快照中保持 `gold_needs_review`，`includedInAccuracy=false`，可用于诊断与后续教研，但不得进入任何准确率分子或分母。

冻结文件以规范化 JSON 计算内容 SHA-256，并对实际文件字节计算文件 SHA-256；文件哈希另写入同名 `.sha256` sidecar。后续盲测运行器必须把“冻结快照文件 + 通过校验的 sidecar”作为唯一金标输入：启动前同时验证快照结构、内容哈希、文件哈希、题目 ID 唯一性和版本，不再从当前正式题库、当前题族、审核草稿或本轮 AI 输出临时拼装或补齐金标；任一哈希不一致或 sidecar 缺失时拒绝运行。

#### 5.8.7 独立金标防锚定与阶段式审核【已确认，已实现】

DEC-033 对 DEC-032 的审核页面和候选展示时点作进一步约束；两者冲突时以本节为准。金标审核数据必须分为四层，不能继续把 AI 预填混入一个可直接“确认现有值”的对象：

1. **正式基线**：保存并展示当前正式题库快照、明确的来源答案或平台核验答案、未经 AI 结论改写的教材原文与位置、正式知识指纹和正式题族事实。正式基线必须标明题目版本与来源，不能把本轮 Agent 选择的证据、选项知识、得分点或候选题族伪装成正式值；
2. **人工首次判断**：审核员在看不到本轮 AI 候选具体内容的条件下，独立提交答案与知识判断，再独立提交题族判断。首次判断保存后不可覆盖，至少记录审核人、时间、所依据的正式基线版本、字段值和说明；正式题目或知识在提交前发生变化时，必须更新基线并重新形成首次判断；
3. **AI 候选**：Agent 1-3 的教材召回、选项知识、得分点、知识判断、题族建议和候选新题族草稿独立保存。人工首次判断提交前，普通详情接口不得返回这些具体候选，前端也不得通过隐藏 DOM、默认勾选、默认选中或样式遮挡提前持有候选；隔离必须由服务端执行，不能只靠界面折叠。AI 召回的教材原文可以作为待核对来源材料展示，但初始必须不勾选，只有审核员主动勾选后才能进入人工金标；
4. **对比后终裁**：首次判断保存后，审核员可以主动展开“与 AI 候选对比”，逐字段查看一致项、差异项和来源。维持原判或对比后改判都要另存终裁事件；改判必须说明依据，且不能改写首次判断。冻结只使用人工终裁形成的 `finalGold`，AI 候选本身永远不是金标准，也不得成为盲测运行器的隐藏答案来源。

“确认现有值”只表示确认正式基线或已经形成的人工值，不能确认尚未揭示的 AI 预填。若仅修正金标解释性标注而不改变正式题目、正式答案、正式得分点或正式知识指纹，不得无条件创建新题目版本；只有正式业务字段变化时才进入 DEC-032 的正式升版与漂移门禁。具体哪些字段属于正式业务事实、哪些只属于金标审计，必须在数据字典中逐项列明。

长页面采用阶段式折叠，页面本身不再新增平行模块：

- 选中题目后，右侧不得继续显示或占用“从左侧选择一道题开始审核”的空白；
- 当前“答案与知识”阶段默认展开，题族阶段折叠且不可操作；第一阶段保存后折叠成包含答案、教材证据数量、题目知识焦点、最小充分知识集、审核结果、审核人、审核时间和题目版本的摘要，并自动展开、定位到“题族裁决”；
- 已完成阶段允许重新打开查看；若重新修改答案或知识，原题族审核立即失效并回到待审，不得继续显示为可冻结；
- 选择题的逐选项区域使用紧凑表格“选项｜角色｜知识关系｜涉及知识”。关系先选，只有“另有选项知识”才展开知识选择器；知识以标签展示，点击具体行后才进入编辑。主观题得分点采用等价的紧凑摘要与按项编辑，长文本和多标签不得造成横向溢出；
- 右侧顶部保留 sticky 题目摘要，至少包含材料/题干、全部选项，以及当前题标题下的完整教材、题型、正式题目版本和知识路径，使审核员滚动到题族区域时仍能核对题目与正式上下文；摘要不能遮挡阶段标题、表单或底部操作；
- 第二阶段提供“保存本题”和“保存并审核下一题”两个明确动作。前者保存后留在当前题，后者只有保存成功才按当前筛选顺序进入下一道待处理题；失败、冲突或当前筛选已无下一题时不得静默跳转。不得继续以普通保存按钮隐式切题；
- 左侧列表只显示序号、题干、盲测层级或数据风险、当前审核阶段，并隐藏长题目 ID；教材、题型、正式题目版本和完整知识路径不得在列表重复展示。阶段至少区分“答案知识待审”“题族待审”“可冻结”“存在争议”及“正式数据已漂移”；风险只描述证据缺失、版本漂移或数据完整性，不提前泄露 AI 结论；
- 版本文案固定区分“金标集目标版本 V1”“当前题目版本 v1”“修订后题目版本 v2”。不得使用脱离对象的裸 `V1/v1/v2`，也不得把已包含 V1 的金标集名称再次拼接版本。冻结后改称“已冻结金标集 V1”。

冻结改为 `prepare -> commit` 两步：

1. `prepare` 只有在全部题目两阶段已形成终态、题族判断仍基于当前知识摘要且没有正式数据漂移时才可执行。它固定审核人、冻结时间、快照 ID、金标集版本、批次修订号和精确快照字节，返回汇总、内容 SHA-256、文件 SHA-256 及短期有效的单次提交令牌，但不创建正式冻结快照、不生成 sidecar，也不启动盲测；
2. 预览必须显示总题数、完成/待审数、确认/修正/争议数、可计准确率、`gold_needs_review`、成熟/单题/无匹配分布、教材分布、正式漂移数、金标集版本、审核人、内容 SHA-256 和文件 SHA-256；
3. 从 `prepare` 到 `commit` 之间，只要任一题的首次判断、终裁、正式题目版本、正式答案、正式知识、题族审核依据、审核人、金标集版本或批次修订发生变化，旧令牌和预览哈希立即失效，必须重新 prepare。令牌过期、重复使用或内容不一致也必须拒绝；
4. `commit` 只能原样写入 prepare 固定的字节，不得重新生成时间、UUID 或序列化内容；落盘后的内容哈希和文件哈希必须与人工确认前看到的预览完全一致，随后才创建同名 `.sha256` sidecar 并将批次置为冻结。commit 到此结束，不自动启动任何盲测。

汇总结果必须互斥。单题分类优先级固定为：任一阶段未完成或知识摘要失效则为 `pending_review`；否则任一阶段为 `disputed` 则为 `disputed`；否则任一阶段为 `corrected` 则为 `corrected`；其余为 `confirmed`。因此 `total = pending + disputed + corrected + confirmed`，`completed = disputed + corrected + confirmed`，`accuracyEligible = corrected + confirmed`，`goldNeedsReview = disputed`。如需统计修改次数，另设审核事件数，不得让同一道题同时进入“人工修正”和“存在争议”两个题数。

#### 5.8.8 逐选项知识关系先判定、知识节点按需标注【已确认，部分实现】

DEC-034 修正“每个选项都必须绑定知识点”的错误前提。选项仍必须完成正确项、干扰项等角色判断，但选项文本可能只是把题目层知识应用到不同材料，并不天然形成独立知识归属。人工可选择三种关系：

1. **仅使用题目知识**（`question_only`）：验证或排除该项只调用题目层已经确认的题目知识焦点与作答最小充分知识集，没有可单独归因的选项知识。此状态不是“没有知识”，也不表示忽略该选项；正式选项知识列表必须为空，不得把题目公共知识机械复制到每个选项；
2. **另有选项知识**（`option_specific`）：验证或排除该项确实需要一项能够单独归因的概念、规则或辨析知识。选择该状态后才展开知识选择器，并且至少选择一个知识节点；只因选项出现某个名词、例词或材料，不足以建立该关系；
3. **暂无法判断**（`undetermined`）：现有教材证据或题目表达不足以判断该项是否有独立知识映射。该项不强制选择知识节点，可以保存不确定说明，并从选项知识准确率和选项级错因推断中排除；它不自动把整道题改为 `disputed`，也不自动取消答案、题目知识焦点、最小充分知识集或题族裁决的计分资格。

系统内部另保留 **待判断**（`unreviewed`）作为导入、迁移和未完成人工判断的过程态，但它不出现在上述人工三选中，也不是一个可提交的人工结论。非争议的答案与知识审核要求每个选择项都已完成角色和知识关系判断；仍有 `unreviewed` 时不得以 `confirmed` 或 `corrected` 提交。整题已经选择 `disputed` 时可以保留未完成的选项映射，并按既有规则整体排除准确率。

字段与兼容规则：

- 每个选项分别保存 `role`、`knowledgeRelation`、`knowledgeNodeIds` 和可选的 `uncertaintyNote`；角色与知识关系是两个独立判断，不能用正确/错误角色推断知识关系；
- `option_specific` 必须有非空 `knowledgeNodeIds`；`question_only` 与 `undetermined` 的正式 `knowledgeNodeIds` 必须为空。切换关系并保存时须清理不再合法的旧知识节点，不能留下界面隐藏但仍参与冻结或诊断的脏值；
- 旧数据中知识列表非空时，只能在原有数据来源层内兼容为 `option_specific`；旧空列表统一迁移为 `unreviewed`，不得自动推断为 `question_only` 或 `undetermined`。AI 候选、正式基线和人工金标仍按 DEC-033 分层，迁移不得把旧 AI 列表带入人工首次判断；
- 新冻结快照必须逐项保存知识关系；缺少该字段的历史不可变快照保持原样，读取时标记为旧协议且不参加选项知识关系或选项知识节点指标，不能为了兼容静默补写并改变旧哈希。

Agent 与下游规则：

- Agent 1 先判断逐选项知识关系，再按需提取选项知识；Agent 2/3 不得把 `question_only` 选项强行补成独立知识，也不得用空列表冒充已判断；
- 专项训练与错因诊断只有在人工确认或有效金标为 `option_specific` 时，才允许把用户所选错误项映射到该项知识。`question_only` 回退到题目知识焦点、最小充分知识集与主题族；`undetermined` 明确为选项级证据不足，不做选项知识推断；
- 盲测评估应分别报告知识关系判断和选项知识节点。关系指标只统计人工已确定的 `question_only` 与 `option_specific`；选项知识节点的精确率、召回率或 F1 只统计 `option_specific`，`undetermined` 和 `unreviewed` 不进入该指标分母。

#### 5.8.9 选项关系 V2、组合题与分项评估【已确认，已实现】

DEC-035 对 DEC-034 的来源分层、在线失败和评估方式作进一步约束；冲突处以本节为准。

1. **唯一事实源与来源隔离**：逐选项或逐原子陈述的 `knowledgeRelation` 是知识关系的唯一事实源。题目模式、正确项角色、知识提示是否非空、节点是否存在和旧启发式都不得反推关系。人工金标、Agent 1 原始输出、Agent 2/3 校核建议和旧数据迁移分别保存；任何一层不得静默覆盖 Agent 1 原始结果或人工首次判断。
2. **新旧数据分流**：新版在线 Agent 输出必须显式覆盖全部预期选项或原子陈述，并只使用 `question_only / option_specific / undetermined`。缺项、重复、非法枚举、选项越界、`option_specific` 缺知识或 `undetermined` 缺说明均属于合同失败；系统最多执行一次携带精确错误清单的约束重试，仍失败则整次标记 `unassessed`，不得降为 `unreviewed`。只有历史数据缺少关系时才迁移为 `unreviewed`；旧知识提示若需保留，必须进入独立 `legacy/raw` 字段，不得据此猜成 `option_specific`。
3. **删除检验**：概念题、应用题或“正确/错误”句式只能作为候选特征，不能成为硬规则。删除某项候选知识后，若题目层最小充分知识仍足以验证或排除该项，则该项为 `question_only`；只有确实必须调用额外知识时才为 `option_specific`。多项共享同一额外知识也不能自动把它并入题目最小充分知识集，仍须在题目层单独通过删除检验。
4. **Agent 权限**：Agent 1 独立保存关键词、作答依赖顺序、题目模式、逐项关系、知识提示与依据。Agent 2/3 在独立字段中逐项返回确认、异议或修正建议，并由协议明确哪一层产出最终候选知识节点及证据；校核建议不能改写 Agent 1 原始输出。`questionMode` 只描述题型结构，不得复用为知识关系模式。
5. **只读整题摘要**：系统可从当前人工草稿或 `finalGold` 自动派生四态计数及“全部仅题目知识 / 全部独立知识 / 混合 / 待判断”；`unreviewed` 与其他状态并存时优先显示待判断，非选择题显示不适用。该摘要不新增可编辑落库字段，也不得读取尚未揭示的 AI 候选。
6. **组合选项**：直接 A/B/C/D 题使用 `choiceStructure=direct_options`。①②③等原子陈述再组合成 A/B/C/D 时使用 `choiceStructure=composed_options`，知识关系只保存在稳定的 `atomicStatements[{key,text,knowledgeRelation,basis,knowledgeNodeIds,knowledgeLabels,uncertaintyNote?,verdict?}]`；`optionComposition[{optionKey,atomicKeys}]` 只保存组合映射，组合答案项不得复制原子知识。正确项、干扰项等答案角色与原子知识关系分开保存。
7. **新版冻结**：新快照必须声明选项知识协议版本。V2 可计分选择题不得含 `unreviewed`，`undetermined` 必须有说明，组合映射引用必须完整且无悬空；不满足时快照非法。历史不可变快照继续按原字节和原哈希读取，允许标记旧协议并排除新增指标，但禁止原地补字段。
8. **评估指标**：关系评估至少报告混淆矩阵、`question_only` 与 `option_specific` 两类 precision/recall/F1、macro-F1、整题关系完全命中率和确定样本错误弃权率。Gold 明确而 Agent 返回 `undetermined` 计错；Gold `undetermined` 不进入主关系分母但单独报告。节点同时报告端到端指标（关系漏判按空预测）和关系命中后的条件指标。
9. **协议验收样题**：在正式 20 题外建立隔离样题，覆盖全部仅题目知识、各项独立知识、混合题、组合选项题和证据不足题；另用成对样例验证共享知识的删除检验。组合题至少覆盖①②③组合和“以上都正确”。样题只验协议与解析器，不进入模型准确率，也不得用于调完协议后反向修改正式 20 题金标。

DEC-035 已于 2026-09-01 完成实现。Agent 1 对直接选项或原子陈述强制输出三态关系，非法合同只允许一次带错误清单的约束重试；Agent 3 逐项独立保存确认、异议与修正，并在存在教材证据时逐项引用证据。组合题按原子陈述保存知识关系、节点和删除检验依据，A/B/C/D 只保存组合映射与答案角色；原子 key、原文全集和组合映射必须与正式题目快照一致，`composed_options` 的组合选项知识必须为空。金标冻结强制校验 V2 协议完整性及 `includedInAccuracy`，盲测报告已展示关系混淆矩阵、两类 precision/recall/F1、macro-F1、整题关系完全命中率、错误弃权率，以及节点端到端和关系命中后条件指标；Gold 为 `question_only` 时错误预测的节点计入端到端假阳性。

- 题包合集页（我的题包）借用知识卡卡集页的**目录 + 双列卡片**编辑形态：目录行就地新建（含子目录）与就地改名、三级层级、长按弹出深色操作栏（重命名 / 添加 / 标题级别 / 移动 / 删除 / 取消）；卡片为双列卡面（题型标签 + 题干 + 来源路径 + 状态与序号），轻点打开（练习 / 录入），长按弹出深色操作栏（编辑 / 添加 / 删除 / 移动 / 取消）；底部“添加卡片”改为深色圆角菜单（新建目录 / 新建子目录 / 新建卡片）；点页面空白处取消选中。**长按后按住拖动可排序**：原位虚化 + 浮起幽灵跟随手指 + 蓝色落点提示（画在卡片下层），卡片可跨目录拖、目录可同级调序、拖进别人卡片区则接管该格起的卡片；拖到上下边缘页面自动滚动，松手停止；拖拽期间页面滚动锁定。选中状态下再点卡片可**加选**，操作栏「编辑 / 添加」只对单张有效，「颜色 / 删除 / 移动」对整组生效，整组拖拽时幽灵卡显示 `×N` 角标；卡片可**上色**（与知识卡同一套 9 色色板 + 无颜色，浅色铺底配同色玻璃边）。顶部**不设**“题目目录”标题栏、也**不设**右上角“···”（分享等收进底部“更多”）；“更多”是**自底部向上划出的抽屉**（分享题包 / 收藏题包 / 从我的资产导入题目）。没有归属目录的卡片统一进“未归档”分组，不会从页面消失；公共题包保持只读，所有编辑入口先提示收藏；**管理题包页已下线**，其编辑能力与「选了题包再录题 / 把题目挂进题包」两个入口都由本页承担；
- 综合训练允许多选科目和教材，调用同一套虚拟综合题池，不复制题目。

用户端目录统一采用“教材目录骨架 + 已确认主题族范围锚点投影”：

- 科目、教材、章、节和知识小点沿用教材知识树作为稳定目录骨架；
- 已确认题族依据人工确认的唯一范围锚点投影到目录，题目只随唯一主题族投影；教材证据锚点、关联题族、题目知识焦点和其他知识标签只作为证据、关系与筛选信息，不增加目录投影。范围锚点可以由题族覆盖知识的最近共同父节点生成候选，但必须人工确认，不能因祖先关系自动采用；
- 父目录数量递归汇总全部下级范围，并始终按稳定题目 ID 去重；一道题即使涉及多个题族或多个知识标签，在同一统计范围内也只能计算一次；
- 待审核、已驳回和候选新题族不进入正式用户目录；题族确认、锚点或主题族变化后，投影随权威关系更新，不复制或迁移题目实体。

目录投影必须同时通过四项门槛：题目是当前教材的有效题，题族定义状态为 `confirmed`，成员归属状态为 `confirmed` 且是唯一主题族关系，并且题族拥有当前教材内有效且已确认的范围锚点。系统从通过门槛的稳定题目 ID 集合出发，投影到范围锚点，再向其全部祖先递归汇总；每个目录范围最终按题目 ID 集合去重。题目正式知识指纹、题族覆盖知识、教材证据锚点、AI `suggested` 候选、普通关联题族、待审核成员关系和无效锚点均不得成为额外目录计数来源。

管理端左侧教材目录徽标与右侧所选目录的“正式投影题数”必须读取同一份递归去重后的题目 ID 集合，并使用相同的教材、目录子树、有效题、题族状态、关系状态与锚点条件。右侧若另行展示“全部状态”“仅当前节点”或题族成员关系等教研工作集，必须单独命名、单独计数，不得复用“正式投影题数”，也不得把多个题族卡片的成员数直接相加冒充目录题数。

归组统计统一使用目录投影口径，并在当前教材范围内按稳定题目 ID 去重：

- **已归组题目**：当前教材有效题中，已经形成有效、已确认主题族目录投影的题目数；同一道题即使拥有多个教材锚点，也只计一次；
- **待归组题目**：当前教材有效题中，没有形成有效、已确认主题族目录投影的题目数；题目可能完全没有题族关系，也可能只有待审核、已驳回、失效、缺少有效锚点或非主题族关系；
- **无题族关系**：待归组题目的子集，表示题目当前没有任何题族成员关系，沿用原“暂未成族/未成族题目”的管理含义；不得再用它代表全部待归组题目；
- 在同一教材和同一有效题范围内，已归组题目与待归组题目互斥且共同覆盖全部有效题；离线题和已合并源题不进入这组统计。

“待归组”和“无题族关系”必须由当前有效题、题族状态、主题成员关系、教材锚点和正式目录现场派生，不得另存一份可独立增删的活动名单。题族状态 V4 中旧 `unresolvedByBook` 仅保留为空对象作为序列化兼容字段，不再参与读取、统计或业务写入；当轮自动生成返回的未解决数量只用于本次反馈，不得成为长期业务事实。已有 `historyByBook` 聚类历史继续保留用于审计。

平台自营和人工审核的题库统一称“平台题库”。不得使用“官方题库”暗示政府、考试机构或教材出版方授权；真实来源单位只在题目、试卷或资料的来源字段中如实标注。

### 6.3 知识库【已实现/部分实现】

- 承载知识卡、作品速览、背诵内容、精选资源、笔记和经审核的共创资产；
- 顶部导航栏不承载“知识库”页面标题：左上角是资源库目录入口，底部胶囊导航承担“知识库”标签；从目录进入某个资源空间后，导航栏显示该空间名（作品速览 / 笔记 / 题包 / 背诵卡），作为该模式下的位置提示；

- 可将适合复习的知识内容加入复习；
- 当前存在种子和兜底内容，不代表正式内容规模已经充足。

### 6.4 复习【已实现/部分实现】

复习是当前默认入口，承担今日进度和学习资产管理。复习工具顺序：

1. 错题本
2. 复习日历
3. 学情分析
4. 知识卡
5. 收藏
6. 番茄时钟（规划中）
7. 自习室（规划中，放在最后）

错题本规则：

- 状态为待纠正、待巩固、已掌握、历史错题；
- 主浏览路径为“科目 > 章节 > 错题”；教材和知识点仍保留为内部元数据和辅助筛选能力；
- 章节列表优先显示错题数量，进入章节后再展示题目列表；
- 点击题目直接进入练习，不保留多余的“开始练习”按钮；
- 重做正确后可移出待处理队列，但历史错题继续保留。

复习日历展示过去、今天和未来的安排；逾期未完成内容滚入今天，并保留已完成历史。

#### 6.4.1 知识卡盒相对新增【已确认，已实现】

- 相对新增目录只改变目录顺序和标题级别，不改变现有卡片数量、内容、顺序或未知扩展字段。

#### 6.4.2 知识卡卡集目录抽屉【已确认，已实现】

- 抽屉内的目录按标题级别组成树：一级标题折叠二级标题，二级标题折叠三级标题；默认全部展开，点开后记住本次展开/折叠状态。
- 点击带有下级标题的目录行切换该行的展开与折叠；点击最末级标题进入该目录的卡片列表。
- 最末级标题的卡片列表按 `01`、`02` 的序号列出卡片题干，空白卡片显示为“空白卡片”；点击其中一张只关闭抽屉并滚动定位到该卡片在卡集中的位置，同时短暂高亮，不直接进入知识卡页或卡片编辑页，由用户在卡集中自行点击卡片。
- 抽屉右上角固定一个折叠/展开图标：点击一键折叠全部目录，再次点击一键展开全部目录；没有下级目录时不执行任何操作。
- 没有任何目录时，抽屉显示“还没有目录”空状态，并提示通过“添加卡片”新建目录。
- 目录抽屉只读取既有卡集目录与卡片数据，不改写目录顺序、标题级别、卡片归属或卡片内容。

#### 6.4.3 卡集选择与目录操作栏【已确认，已实现】

- 长按卡片进入多选、或长按目录标题进入目录整理后，出现黑色操作栏：卡片多选时为“编辑 / 添加（仅选中一张时出现）/ 删除 / 移动 / 取消”，目录整理时为“重命名 / 添加 / 标题级别 / 移动 / 删除 / 取消”。卡片操作栏不再提供“置顶”。
- 点击页面空白处（卡片与目录标题以外的内容区）等同于“取消”：先关闭已展开的深色菜单，再关闭操作栏；点击卡片、目录标题、操作栏按钮或浮层内部不会误触取消。
- 目录整理操作栏的“添加”弹出两项菜单：**新建卡片**（在该目录内新增一张空白卡片并直接进入卡片编辑页，卡片即归属该目录）与**新建子目录**（在该目录的完整子树之后新建下一级目录，级别最高到三级；三级标题不再提供新建子目录，只提示）。**新建目录不弹窗**：选出后直接在该位置生成一条空白目录，就地在目录行里输入名称。
- **重命名目录同样不弹窗**（取代 DEC-060 中“改名为空目录仍走原来的重命名入口”的表述）：点击目录标题、或目录整理操作栏点“重命名”，都直接把该行变成行内输入框——沿用该行原来的字号与层级缩进、预填当前名称、光标停在名称末尾、立即聚焦弹出键盘；键盘“完成”或失焦即提交（样式与卡集列表页的文件夹行内输入一致：浅色圆角描边盒）。留空或没改保持原名，重名提示“该目录已存在”并放弃这次输入；提交以**输入框所在行**为准（`data-title`），不会因为先点了另一行而改错目录。
- 操作栏默认出现在所按卡片或目录标题的**上方**；上方空间不足（例如按的是紧贴导航栏的第一行）时出现在其下方，并始终限制在视口内，不越出底部。
- 多选过程中每**点选一张新卡片**，操作栏移动到该卡片的上方（沿用同一套上方优先、下方兜底规则），并从新的位置继续跟随滚动；取消选择某张卡片时操作栏保持原位。
- 操作栏出现后**跟随内容一起上下滚动**，不瞬移：向下滚动时它随内容逐渐上移，滚到顶部自定义导航栏下方后停住并保持可见；向上回滚时它随内容一起下移回到原来的位置。
- 操作栏是浮层，不参与文档流，出现和消失都不得改变卡片内容的原有位置。
- 横向位置沿用原有规则：多选时按所选卡片所在列左对齐、居中或右对齐，目录整理时居中。
- 操作栏只读取当前选中状态；取消、删除、移动或跳转定位后按原逻辑关闭。
- 操作栏里的“添加 / 标题级别 / 移动 / 移动到目录”等选择不再使用微信系统 ActionSheet，改为与操作栏同一视觉的深色圆角菜单：出现在操作栏正下方，按操作栏对齐方式左/中/右对齐；条目超过剩余高度时在菜单内滚动；点击条目执行并关闭，点击菜单外任意位置关闭。多选时“移动到目录”列出全部目录供选择，不再按数量切换为输入框。
- 知识卡卡集页底部悬浮栏的第三个条目由“整理”改为“**分享**”（原生 `open-type="share"` 按钮，点击直接唤起微信分享，分享内容为当前卡集的标题与路径）；目录整理仍可长按目录标题进入，能力没有减少。
- **卡片颜色**：卡片操作栏提供“颜色”，点开是深色面板里的 10 个色点（第一个“无颜色”），色板与“选择卡盒颜色”同一套浅色；上色后卡片**整块铺浅色底**，类型标签用同色系深色，未上色的卡片保持白底。颜色写在卡片自身的 `color` 字段上，可多选批量涂色，也可用“无颜色”清除。
- **底部「更多」抽屉**：点击底栏“更多”从下往上滑出抽屉，分“卡片操作 / 样式设置 / 卡盒管理”三段；本轮只落视觉骨架，条目点击提示“该功能开发中”。卡盒颜色（统一颜色 / 彩虹色）与旧命名色的迁移在“样式设置 → 更换颜色”里实现。
- **卡盒颜色入口（两处）**：卡集列表页**选中工具栏**里有「颜色」（编辑 / 删除 / 移动 / 置顶 / **颜色** / 取消），选中几个卡盒就同时上几个色；卡集页与卡集列表页的底栏「更多 → 样式设置 → 更换颜色」则打开统一颜色 / 彩虹色面板。两处共用同一套 9 色浅色板。
- **浅色板取色原则**：上色用的是统一明度（≈92%）、色相校准、彩度略提的干净浅色（避免灰绿、灰玫瑰这类“发暗显脏”的取色）；卡面是**「四层光/暗 + 浅色」的玻璃/水晶质感**——主高光弱而收（`.42`，58% 处消失）、**小而锐的镜面亮点**（玻璃区别于塑料的关键）、底部透光、**背光侧同色系折射暗部**，再叠 CSS inset 边缘受光与右下同色暗部；**高光峰值不得贴边**（真机会把左上角洗白、边界糊掉），上色卡片另加同色系低透明度玻璃边（`--card-edge`，26% 的 accent）；**不使用投影、不使用 `backdrop-filter`**；上色的卡片与卡盒不叠暖灰描边（白底卡片保留描边以区分背景），选中蓝框由样式表的 class 特异度保证（边框色只能走自定义属性下发，不能写进行内样式）；次要文字用中性灰；页面底色接近白（`#fdfcfa`），卡片圆角 28rpx（卡集页 20rpx）。
- **卡集列表页的「更多」抽屉**：同一套从下往上滑出的抽屉，内容为“卡盒操作（新建卡盒 / 整理卡集 / 全部卡集）/ 样式设置（更换颜色）/ 卡盒管理（管理文件夹 / 新建文件夹 / 重命名文件夹）”。与卡集页不同，这里的条目**直接复用页面已有能力**（不占位），只有“更换颜色”等颜色面板尚未接线时提示“该功能开发中”；进入“全部卡集”视图后不允许重命名文件夹，只提示先进入某个文件夹。

#### 6.4.4 卡集卡片与目录长按拖拽排序【已确认，已实现】

- 长按卡片或目录标题后**继续移动手指**（超过约 10px）进入拖拽：原位置保留一个**虚线淡化的占位**（卡片变淡、虚线框），另有一张**放大 5% 的浮起卡片**跟随手指，此时操作栏自动隐藏；只长按不移动时仍按原逻辑进入多选或目录整理。
- 拖拽中的插入位置用**蓝色提示条**表示，规则固定：
  - 落在某一行两列**中间**时，显示左侧卡片右边缘的竖向蓝条（表示插入到这两张卡片之间）；
  - 落在某一行**最前方**或整段**末尾**时，显示贯穿内容宽度的横向蓝条（表示插到这一行/这一段的前面或后面）；
  - 落在空目录上时，在该目录标题下方显示横向蓝条。
- 蓝色提示条绘制在卡片**下层**（卡片与标题压住提示条），所以看上去像从卡片缝隙里透出来，不会盖住卡片内容。
- 松手即按提示条位置落位：卡片可以在同一目录内换位，也可以直接拖入其他目录；目录拖拽分两种落点：
  - 落在**目录标题之间**：只调整目录顺序，标题级别不变，子目录随父目录整体移动，**不改动任何卡片的所属目录**；
  - 落在**某个目录的卡片区域内**（某张卡片前面）：该目录**接管**从这张卡片起的卡片——那些卡片改属被拖入的目录，被拖入目录排到源目录之后并继承源目录的标题级别；原目录保留它前面剩余的卡片，被清空也不删除。
- 拖拽期间页面**冻结滚动**：长按触发的瞬间（手指还没开始移动时）就锁定页面根节点滚动，因此拖拽全程不会产生任何页面滚动，被拖元素严格跟随手指；手指抬起时立刻恢复滚动。只长按不拖拽时页面照常可以滚动，不影响多选后继续浏览。
- 拖拽中手指靠近顶部或底部边缘时，页面**自动向上/向下滚动**（越靠边越快），便于把卡片或目录移到当前屏幕之外；松手立刻停止自动滚动，页面停在当前查看位置。
- 拖拽前后不新增、不删除卡片或目录（目录接管卡片只改归属、不复制内容）；拖拽成功后关闭操作栏并提示结果，拖拽被取消时保持原样。
- 落点计算始终按当前滚动位置实时校正，保证提示条与实际落位一致。

#### 6.4.5 卡集列表页长按拖拽排序【已确认，已实现】

- 卡集列表页（“全部卡集 / 文件夹”网格）复用知识卡卡集页同一套长按拖拽交互：长按卡集继续移动手指进入拖拽，套用相同的“原位置虚线淡化占位 + 放大浮起卡片跟随手指”、蓝色提示条规则（两列之间竖条、行首或末尾通栏横条，且绘制在卡片下层）、滚动冻结与边缘自动滚动。
- 拖拽落到某个卡集前面或后面即完成排序；排序按“与哪一个卡集相邻”记录，因此在某个文件夹或搜索结果的子集里拖动时，只调整该卡集在全量列表中的相对位置，不会打乱其他卡集。
- 点击页面空白处等同于取消：先关闭展开的文件夹列表，再取消卡集多选与操作栏；点击卡集、导航、搜索框、操作栏按钮和浮层内部不会误触取消。
- 拖拽期间卡集操作栏**隐藏**：该操作栏在文档流中占位，因此拖拽时采用“保留占位、内容不可见”的方式隐藏，避免网格跳动导致落点几何失效；拖拽取消时操作栏按原状态恢复显示。
- 卡集列表页的卡集操作栏本轮保持原状（编辑 / 删除 / 移动 / 置顶 / 取消），未同步知识卡页删除“置顶”的调整。

#### 6.4.6 卡集列表页版式与卡集翻面【已确认，已实现】

- **留白与密度**：页面左右边距 16px（32rpx）；卡片间距 12px（24rpx）；顶部导航到首个内容（搜索框）间距 28–36px（60rpx）；卡片纵向高度 `min-height` 260rpx，保持略扁但不过薄的卡形；内容不足时保留大片空白，不压缩、不居中堆叠。
- **背景**：页面底色为接近白色的暖灰（`#f8f6f3`），并叠加极淡的大面积几何圆弧（右上白色大圆、左下细描边大圆环）作为背景装饰，装饰层不接收触摸、不参与布局。
- **投影**：投影只用于底部悬浮导航栏；卡片、搜索框一律不加投影，卡片改用极浅暖色描边区分层次。
- **卡集翻面**：卡片右上角原本的装饰性镂空圆（选择圈）改为**翻面按钮**（复用 `card-flip.svg`，圆形浅底），与左上角的卡片张数同处一行（常规文档流，不遮挡标题），点击翻到卡集背面；**背面不重复卡片张数**：头行左侧改为**「简介」标签**（与正面张数同一位置、同一字号），右侧仍是翻面按钮，下方依次是简介正文（为空时显示“暂无简介”）与作者（缺失时回落“我的整理”，并固定在卡片底部）。正面自上而下为**张数 + 翻面按钮 → 标题 → 掌握度 → 进度条**（标题与上方按钮行间距 12rpx，整体紧凑），不再显示“专业课 / 通识”学科标签；**标题使用卡片整行宽度（不得附加右侧留白）、最多两行**，超出以省略号收尾，避免长标题折成三行或首行提前折行造成卡片高低不齐；卡片纵向高度 `min-height` 260rpx，保持略扁但不过薄的卡形。翻面按钮用 `catchtap`，不会误触打开卡集或取消选择；翻面只影响当前这张卡集，且是临时状态（切换文件夹或搜索后回到正面）；进入多选时翻面按钮隐藏，选中状态改由卡片蓝色描边表达。
- **底部导航**：原来右下角的黑色圆形“＋”悬浮按钮改为底部悬浮导航栏（复用知识卡卡集页的悬浮胶囊样式，含唯一投影），提供“**新建**”（主按钮，点击进入新建卡集页）、“**分享**”（原生分享按钮）与“**更多**”（管理文件夹 / 新建文件夹 / 重命名当前文件夹）。打开多选工具栏时底部导航栏隐藏。
- **卡片对齐**：卡片为纵向弹性容器，掌握度与进度条固定在卡片**底部**（内容多时也不上浮），同一行两张卡片的进度条必须对齐；进度条距卡片下内边距保持 24rpx 的呼吸空间。
- **选中态**：多选时被选中的卡集显示 **3rpx 蓝色描边 + 极浅青底**（`#2f9fff` / `#f2fbf8`），由于卡片底色是白色、描边压过默认的 1rpx 暖灰描边，选中与未选中的差异必须一眼可辨；选中态不使用投影。
- 学科标签不再在列表卡片上展示；仍保留在卡集自身的数据里。

## 7. 学习与复习引擎

### 7.1 综合题池【已确认，部分实现】

- 综合题池是跨科目查询能力，不是第二套题库；
- 训练范围中的多科目/教材选择和复习页的综合训练入口调用同一个服务；
- 查询支持知识点、题型、难度、来源、最近做过过滤和数量限制；
- 当前已有跨范围抽题能力，但题族驱动、诊断蓝图和置信度仍未闭环。

### 7.2 错题归因与推荐【已确认，待整改】

- 错题首先归因到题目的主题族；
- 系统能够知道题目的主题族；只有错误选项已经人工确认存在 `option_specific` 映射时，才能进一步使用该项知识标签，但仍不能仅凭一次错误准确断言用户的真实错因；
- 错误选项为 `question_only` 时回退到题目核心/必需知识和主题族；错误选项为 `option_specific` 且与题目主题族分属不同知识时，依据已确认题族的知识标签和人工案例动态计算候选训练关系，并同时保留不确定性说明；`undetermined` 不做选项级推断；
- 动态计算只能推荐已确认题族；没有足够映射或案例时回退到主题族或“证据不足”，不得把选项中出现的全部知识都推送给用户；
- 无法知道用户为什么错时，只能给出可解释的可能原因，不得伪造精确诊断；
- 知识树用于定位材料，知识档案用于解释边界，二者不直接替代题族推荐。

### 7.3 题族训练闭环【规划中】

```text
知识回顾 -> 基础校准题 -> 原题/同类题 -> 变式题 -> 延迟复测
```

当前题族成员与层级可以管理，但用户侧尚未形成完整自动推荐闭环。

题族确认与训练能力必须分开判断：

- 已确认单题题族可以进入教材目录投影、主题族归因、原题复习和延迟复测；
- “同类训练”只有在排除当前题后，题族中还存在至少一道可用的原型题或同类题时才启用；
- “变式训练”只有在排除当前题后，题族中还存在至少一道可用的变式题时才启用；
- 某项训练缺少真实额外成员时，只禁用该项能力并明确显示“暂无其他同类题”或“暂无其他变式题”。可以回退到原题延迟复测，但不得跨题族硬凑、复制题目或把其他能力一并判为不可用。

### 7.4 学情分析【部分实现】

- 页面顶部中间固定显示“学情分析”并保留返回按钮；雷达卡片左上角的当前学科名称与下拉箭头承担学科切换，内容区不重复显示页面标题，也不新增独立学科切换行；
- “学习趋势”支持切换统计周期：**7 天 / 14 天 / 30 天**（默认 14 天）。图表展示所选周期内的每日趋势，对比口径为“最近 N 天 vs 此前 N 天”，文案随所选周期显示为“较前 N 天…”“近 N 天暂无…”；
- 学情结论区分未测、证据不足、初步风险、薄弱、改善和已掌握；
- 结论应说明来自哪些题目、题族和时间跨度；
- 当前主要依据已有作答记录做统计和建议，不是经过真实样本校准的精准诊断系统。

### 7.5 首次诊断与计划【规划中】

旧报告提出“扫描题 + 动态追加 + 可解释置信度 + 7 天计划”，目前只作为待验证方案。正式方案需另行确认抽题蓝图、最小证据量、停止条件、报告文案和效果指标。

## 8. 管理后台

### 8.1 一级模块【已实现】

### 8.2 统一题库工作区【已确认，已实现/部分实现】

题目与题族不再作为彼此割裂的一级库。题库管理内部统一提供题库、知识档案、AI 巡检、教研规则。

在题族中发现题目问题时，应能直接查看和编辑题目；题目详情显示知识路径、主题族和关联题族。搜索题目时同时显示题族归属。

- 按“科目 > 教材 > 教材节点 > 题族集（可嵌套） > 题族 > 题目”组织；没有归入题族集的题族仍直接显示在其教材节点下；
- 目录支持折叠；
- 左侧教材目录徽标固定显示同一目录子树的正式投影题数；右侧正式统计必须与其同源、同范围并完全一致，其他状态或成员关系统计使用不同名称；
- 题族支持创建空题族、加入题目、批量归组、批量移动成员、随确认/保存调整目录主锚点和删除；
- 题族选择支持按名称和知识路径搜索，并合并同一语义题族的历史重复项；
- 题族工作区搜索按“题族名称 > 题族判别焦点、覆盖知识或范围/证据锚点 > 题干 > 选项或题目 ID”的相关性排序，并在题族行标明命中来源；搜索结果中的题族默认折叠，只有审核员主动展开后才展示成员。成员题命中时先展示本次命中的题，并提供查看全部成员的入口，不得因自动铺开前一个题族而把后续题族结果推离首屏；
- 题族集支持创建空集、嵌套、搜索成员、原子迁入、移出成员和安全解散；间接成员不得在上级集重复直属迁入；成员区使用“当前内容 / 可归入内容”标签页并默认展示候选；左侧教材目录仍保持纯知识树，不把题族集伪装成教材节点；
- 多选操作栏保持可见；
- 题目点击进入查看/编辑，避免跳转到另一个独立模块。
- 题族详情和编辑页明确展示并维护六组定义事实，其中判别焦点、覆盖知识、范围锚点和教材证据锚点不得隐藏在旧单一目录字段中；
- 题族成员卡的指纹区域为只读比对区：展示题目当前正式字段、题目版本与真实 `confirmed` 题目知识焦点/最小充分知识集，将题族判别焦点、覆盖知识、范围锚点和本题贡献知识作为另一组正式信息，并把 AI 候选单列为未确认；按主题族/关联题族规则判断不兼容时只显示警告和“前往题目编辑”，不在题族页内改写题目指纹；
- 题族判别焦点、覆盖知识、范围锚点和教材证据锚点均使用可检索组件；范围锚点变化随确认/保存原子生效，不设置独立搜索框或独立移动按钮；
- 单题题族的主操作明确显示“确认单题题族”，并提示“确认后进入教材目录与原题复习，暂无其他同类/变式题”；确认后使用“已确认 · 单题待扩充”展示，其中“单题待扩充”是派生质量标记，不是第四种审核状态；
- 题族成员摘要分别显示原型题、同类题和变式题数量；不得用无说明的“保存题族”掩盖单题可以确认的事实。用户侧同类/变式入口不可用时必须说明缺少哪类额外成员；
- 题族状态筛选由审核员主动控制；删除题族、加入或移出成员、批量归组或移动、确认题族、调整目录主锚点和手动刷新后均保持当前筛选，不得由后台操作擅自切回“全部状态”；
- 题族工作区分别提供“题族定义状态”和“成员归属状态”信息；已确认题族允许直接筛选并连续审核 `pending_fit` 成员，成员审核完成后不得要求再次确认题族定义；
- 题目编辑支持多选“插本 / 考研”考试标签并兼容旧单选数据；
- 教研规则的草稿、已启用和已停用状态均提供带审计记录的删除入口。

### 8.3 题目完善【已实现/部分实现】

- AI 只生成字段级建议稿；
- 人工可逐项采纳，不应整题覆盖；
- 已核验来源答案必须保留；
- 采纳涉及题干、选项、答案或正式知识指纹的修改后创建题目新版本，并使该题在受影响题族中的成员归属及贡献知识进入待审核；题族定义事实没有变化时不得使整个题族退回审核。

### 8.4 管理端发布阻断项【待整改】

- 正式环境必须增加管理员登录、权限、真实操作者身份和访问限制；
- 危险操作必须二次确认并写入操作日志；
- 管理接口不得以开放 CORS 和无鉴权状态直接暴露公网。

## 9. AI、隐私与合规边界

### 9.1 AI 使用原则【已确认】

- AI 聚焦辅助解析、辅助评分、教材检索、内容完善和后台归类，不做泛化聊天主入口；

- AI 输出显示来源、证据和置信状态；
- 未经明确授权，私人答案、笔记、对话和反馈不得用于训练；授权默认关闭、可撤回并在使用前去标识化。

### 9.2 账号与隐私【已确认，部分实现】

产品必须常驻提供隐私政策、个人信息收集清单、第三方信息共享清单、账号注销入口、客服与反馈入口。

个人信息范围至少覆盖微信登录标识、授权头像昵称、设备信息、学习记录、AI 输入与结果、额度流水、投稿活动、反馈内容、联系方式和截图；正式支付后还包括订单与交易记录。

用户应能查询、更正、复制、导出和删除个人信息。注销必须撤销会话，并对学习状态、投稿、AI 任务与对话、反馈联系方式和截图等执行删除或去标识化；依法必须保留的数据应单独保存并明确期限。

当前注销尚未覆盖全部散落数据，隐私政策也缺运营主体、完整第三方清单、精确保存期限和政策变更通知，属于上线前阻断项。

### 9.3 客服与反馈【已实现/部分实现】

### 9.4 内容版权【已确认，待持续核验】

### 9.5 备案、许可与平台类目【待确认】

经营范围不等于行政许可结论。ICP备案、增值电信业务许可、小程序备案、微信服务类目、数字内容和生成式 AI 相关要求必须在正式上线与收费前分别核验，不能仅凭经营范围写死“无需 ICP 许可证”。新增视频、直播、人工答疑或付费辅导前必须重新评估服务性质和资质。

## 10. 数据、落库与运行基线

### 10.1 本地运行【已确认】

- 本地开发唯一标准端口为 `3212`；
- 管理后台：`http://127.0.0.1:3212/admin/`；
- 健康检查：`http://127.0.0.1:3212/health`；
- 其他端口只允许短时隔离验证，完成后必须关闭，不得成为新功能的长期入口。

### 10.2 环境与密钥【已确认】

- 本地、测试和生产环境分离；
- 生产环境使用 HTTPS、微信合法域名和正式 AppID；
- AI 密钥、微信 Secret、数据库密码和文件服务 Token 只在服务端环境变量保存；
- 代码不得写死个人本机或局域网地址作为生产默认值。

### 10.3 存储边界【已确认/部分实现】

- 本地开发当前使用 `.runtime/*.json`；
- 生产目标以 PostgreSQL 为业务数据源；
- K-Vault 或对象存储只承载文件和文件元数据，不替代业务数据库；
- JSON 与 PostgreSQL 切换时必须停止写入、完整导入和校验，不允许两个数据源同时独立写入；
- 当前 PostgreSQL 仍以业务 Store 文档快照为主，只适合单写实例，尚不是最终正规化模型。
- 退役派生索引等一次性维护必须默认只读预演；显式执行前保存原文件快照与 SHA-256，使用并发变更校验和原子替换，执行后验证除协议版本和目标兼容字段外的业务事实哈希不变，并保留维护清单。不得直接手改 `.runtime`。

### 10.4 统一落库协议【产品原则已确认，文件模式样板已实现，PostgreSQL 待实现】

文件开发模式已经接入跨知识结构、题族、巡检结果、Agent 4 经验、知识档案增量和操作日志的统一提交协调器。管理端为同一次审核生成稳定 `commitId`；服务端先持久化 `prepared` 快照，再执行六类写入，任何一步失败都整体回滚，全部业务写入成功后才将巡检结果标记为已采纳并将提交标记为 `committed`。相同 `commitId` 与相同请求会返回首次回执，相同 ID 被用于不同请求时返回冲突；服务重启会优先恢复遗留的 `prepared` 提交，再恢复普通中断任务。

每次巡检还会按题保存当时的知识指纹签名和人工题族成员修订号。采纳前必须逐题复核：同题知识归属或题族成员关系在巡检后发生人工变化时，旧建议返回过期且不得覆盖人工结果；历史待审核记录缺少逐题基线时同样必须重新巡检。其他题目的自动成族或重算不得使本题建议误过期。管理端在保存请求结束前冻结整张审核弹窗，拦截改选、关闭、取消、`Esc` 和切题，并以请求与弹窗双重身份校验异步响应。

该实现仅限本地文件存储、单 API 进程和单写者样板。人工采纳在进程内全局串行；回滚未完成时阻断后续写请求。PostgreSQL 尚无跨 Store 原子事务，当前明确拒绝在 PostgreSQL 模式执行该采纳接口，不得据此宣称生产落库已经完成。

后续协议暂命名为 `ClassificationCommitV1`：

- 每次提交有唯一 `commitId` 和 `schemaVersion`；
- 保存操作者、时间、题目 ID/版本、巡检结果 ID，以及知识树、教材正文和题族基线版本；
- 同时保存题目知识焦点、最小充分知识集、主题族、作答必需关联题族、普通关联题族、逐成员贡献知识或待归组；
- 同时保存人工调整依据、Agent 4 案例/纠错/规则例外、档案增量和操作日志摘要；
- 状态至少包含 `prepared`、`committed`、`failed`；
- 同一 `commitId` 重试不得重复写入；
- PostgreSQL 使用同一事务，或使用事务发件箱和明确补偿机制；
- 文件开发模式使用持久提交日志，并能在启动时恢复或回滚；
- 全部业务写入成功后，最后一步才把巡检标记为已采纳。

产品必须保证一次人工采纳要么完整成功，要么不产生正式结果；重复提交不得重复写入，失败后必须能够识别、恢复或回滚。`ClassificationCommitV1` 是当前技术工作名，不代表其全部字段已经冻结。

分阶段执行：

1. 当前样板阶段已在文件模式实现持久提交日志、幂等重试、失败状态和启动恢复，不以完成全面 PostgreSQL 改造作为分类准确率整改的前置条件；
2. 正式上线前完成 PostgreSQL 原子事务或等价的一致性方案，将 Agent 4 经验 Store 纳入统一持久化，并完成历史数据迁移和校验；
3. 当前 PostgreSQL 未接入巡检经验 Store，Agent 4 对话、规则、案例、纠错和例外存在重启丢失风险，属于正式上线 P0 阻断项。

### 10.5 数据版本与过期【已确认，部分实现】

题目版本、来源答案、教材 PDF/OCR、知识树、知识档案或题族语义/成员/版本变化，都应使实际依赖受影响内容的建议、核验或确认关系进入待复核。题族定义版本与逐成员归属版本必须分开：成员或成员贡献变化优先只推进对应题目的成员归属修订，只有题族判别焦点、覆盖知识、范围/证据锚点、考查动作或边界等定义事实变化才推进定义版本并失效全部成员。优先根据引用片段、事实声明、档案版本、题族定义版本和成员归属版本精确传播失效；无法证明未受影响时，再扩大复核范围。过期记录保留历史并说明原因，不应无解释堆积或直接删除。

当前文件模式已实现逐题知识指纹与人工题族成员修订基线：同题人工改归会精确失效，别题自动重算不会连带失效；没有该基线的历史巡检建议不得继续采纳。

重复题合并必须以预检时的规范题版本、全部源题版本、题族成员修订号和各关系 Store 基线为提交条件。任一基线变化都返回版本冲突并要求重新预检，不得用旧计划覆盖新修改。合并影响到的题族必须退回待审核并推进成员修订号；依赖源题或受影响题族的未采纳建议进入过期状态并注明“题目已合并”或“题族成员已变化”，历史记录继续保留。

### 10.6 题目合并落库协议【产品原则已确认，文件模式与 PostgreSQL 待实现】

题目合并提交暂命名为 `QuestionMergeCommitV1`。它与巡检采纳使用相同的完整、幂等、可恢复原则，但拥有独立的提交类型和关系迁移清单，不得伪装成普通题目编辑或串联多个管理接口完成。

- 每次提交使用唯一 `commitId` 和 `schemaVersion`，保存操作者、时间、合并原因、规范题 ID/版本、全部源题 ID/版本、关系基线、明确的主题族裁决和请求内容哈希；
- 服务端在任何写入前生成完整迁移计划，逐项校验同教材与重复题资格、源题和规范题状态、版本、合并映射、循环、主题族唯一性、关系适配范围及待迁移数量；
- 文件模式先持久化 `prepared` 快照，快照必须覆盖题目 Store、全部受影响的关系 Store、题族成员修订与审核状态、合并映射和操作日志；之后才执行迁移、去重、失效传播和源题离线，全部成功后标记 `committed`；
- 任一步失败必须用快照整体回滚并记录失败阶段；服务启动时优先恢复或回滚遗留的 `prepared` 合并，恢复未完成前阻断新的题目合并写入；
- 相同 `commitId` 与相同请求重试时返回首次回执，不得再次迁移；相同 `commitId` 携带不同请求时返回冲突；已经合并到同一规范题的源题再次提交应幂等返回现有映射；
- 操作日志至少保存提交状态、合并前后题目状态、关系迁移与去重数量、主题族冲突裁决、受影响题族和其他关系范围、失效记录数量、回滚或恢复结果，以及规范题与源题的可追溯映射；
- 运行数据必须通过正式 API 和 Store 修改，不得直接手改 `.runtime` 文件。真实数据执行前后应保留可核验快照与哈希；
- PostgreSQL 模式必须把题目、关系、映射、题族失效和操作日志纳入同一事务，或使用事务发件箱与经过验证的补偿机制；该能力完成前不得宣称题目合并已经生产可用。

## 12. 产品验收原则

任取一道进入样板范围的正式题，应能够回答：

1. 题目来自哪里、当前是什么版本；
2. 哪个答案是来源答案，AI 是否仅为补充；
3. 对应教材、目录、页码和原文证据在哪里；
4. 题目知识焦点及其 `core / scope_anchor` 角色、最小充分知识集是什么；
5. 主题族和关联题族是什么，为什么这样归类；
6. 难度、考频和置信度如何表达；
7. 用户答错后下一步练什么；
8. 谁在什么时候审核或修改过；
9. 数据变化后如何判定旧结论过期；
10. 一次人工采纳能否完整、幂等且可恢复地落库。

对外能力必须以真实数据、可运行链路和验收结果为准。页面存在、按钮存在、模型曾返回一次或测试中有模拟数据，都不能单独证明功能已经生产可用。

## 14. 术语表

| 术语 | 统一含义 |
| --- | --- |
| 教材知识树 | 教材中的位置与导航结构 |
| 知识档案 | 规范概念、边界、关系与教材证据 |
| 题目知识焦点 | 题目正式知识指纹的唯一焦点节点；必须显式标记 `core / scope_anchor`，旧记录缺省为 `core` |
| `core` 题目焦点 | 题目最直接考查的知识节点；必须属于最小充分知识集并由主题成员贡献承载 |
| `scope_anchor` 题目焦点 | 跨知识题的范围组织锚点；不自动进入最小充分知识集，不参与联合覆盖，也不要求主题成员贡献承载 |
| 作答的最小充分知识集 | 可靠作答实际需要调用的最小知识集合 |
| 题族判别焦点 | 同族成员共同使用的稳定判别规则或训练能力，不等于教材父目录 |
| 题族覆盖知识 | 一个题族允许承载的明确知识节点范围，可以大于单个成员题的最小充分知识集 |
| 题族范围锚点 | 题族在教材骨架中的唯一组织与目录投影位置；只管范围，不参与作答知识覆盖 |
| 成员贡献知识 | 某道题在某个主题族或作答必需关联题族中实际由该关系承载的最小充分知识子集 |
| 题族 | 以相同判别焦点、覆盖知识范围和考查动作为基础，并用纳入/排除边界持续收紧的语义分类；可以只有一道已确认原型题，单题时标记待扩充/样本不足；普通人工确认允许边界后补 |
| 题族集 | 绑定教材知识范围、用于组织题族和下级题族集的树形容器；不复制题目或改变题族事实归属 |
| 主题族 | 一道题唯一的主要训练和错因归属 |
| 作答必需关联题族 | 主题题族之外，可靠作答仍必须调用的考查方向；与主题题族共同覆盖整题最小充分知识集，并参与专项训练与盲测计分 |
| 普通关联题族 | 相似、易混、前置或教研参考关系；不参与最小充分知识覆盖、专项训练或盲测题族命中计分 |
| 已归组题目 | 当前教材有效题中，已经形成有效、已确认主题族目录投影的去重题目 |
| 待归组题目 | 当前教材有效题中，没有形成有效、已确认主题族目录投影的去重题目；不要求完全没有题族关系 |
| 无题族关系 | 待归组题目的子集；题目当前没有任何题族成员关系，沿用原“暂未成族/未成族题目”的管理含义 |
| 综合题池 | 跨范围查询形成的虚拟题池，不复制题目 |
| 平台题库 | 薯考平台自营、收录并按平台规则审核的题库，不表示考试机构官方授权 |
| 来源答案 | 原卷、教材或明确来源提供的答案 |
| 平台核验答案 | 经平台人工审核确认的答案版本 |
| AI 补充答案 | AI 生成且明确标注、不能覆盖来源答案的内容 |
| 确认案例 | 人工确认后用于后续检索和匹配的题目特征与归类 |
| 规则例外 | 人工结论与已启用规则冲突时保存的例外记录 |
| 候选新题族草稿 | Agent 找不到合适题族时提出的判别焦点、覆盖知识、教材定位、考查动作、边界及本题贡献建议；人工确认前不是正式题族 |
