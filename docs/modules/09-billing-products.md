# 订阅商品与套餐组

## 1. 规则入口

产品手册 §9.6 的商品与订阅规则、§0.4 DEC-107 的订单与赠币分账，以及「同一套餐多条有效期、价格和赠币规则」是本模块的权威口径。

## 2. 数据归属

- `packageKey` 标识套餐组；`packageName`、考试项目、商品类型、范围、科目和教材是组内共享资料。
- 每条订阅商品是一个规格，以稳定的 `product.id` 供购买、订单和权益引用；期限、价格、赠币、赠币有效期与上下架状态由规格独立配置。
- 豆币充值商品归入**唯一的**「豆币充值」组（组标识固定为 `bean-recharge`，组名可在后台「编辑组」改），与订阅套餐组分开；豆币组没有考试项目/范围/科目/教材，也不做期限去重。组内每条规格仍是独立商品，`product.id`、价格、豆币数量与上下架状态不变，用户端仍逐条展示与购买（合并的是后台分组，不是把多个档位并成一个商品）。

## 3. 操作路径

- 后台商品表按 `packageKey` 展开规格；「新增套餐组」同时创建第一条规格，「新增规格」继承组资料。
- 组资料通过 `POST /api/admin/billing/packages/:key` 一次更新全部规格；规格仍走 `POST /api/admin/billing/products`。
- 同组不能有两个相同期限的规格；组内范围冲突被服务端拒绝。订单仍按具体规格 ID 保存购买时的商品名与金额。
- 豆币充值组与订阅套餐组共用同一套操作（收起/展开规格、编辑组、新增规格）：豆币组的「编辑组」只能改组名，走 `POST /api/admin/billing/packages/bean-recharge`；「新增豆币充值」与组内「新增规格」创建的豆币商品都由服务端固定归入该组（组名继承组内现有值，单条规格改不了组名）。

## 4. 代码与测试

- Store：`apps/api/src/billing-store.js`；后台路由：`apps/api/src/server.js`；PostgreSQL 快照写方法：`apps/api/src/postgres-persistence.js`。
- 后台：`apps/admin/index.html`、`app.js`、`styles.css`。
- 豆币组一次性落盘迁移：`scripts/migrate-bean-recharge-group.js`（默认干跑，`--write` 前先写 `.runtime/billing.json.bak-<时间戳>`）。
- 回归：`tests/billing-store.test.js`、`tests/api.test.js`、`tests/admin-billing-ui.test.js`、`tests/billing-bean-group.test.js`、`tests/postgres-persistence.test.js`；隔离浏览器核对：`tmp/verify-billing-group-ui.js`、`tmp/verify-billing-package-row-bg.js`（套餐组行底色逐项可见性）、`tmp/verify-bean-recharge-group.js`（豆币组合并逐项可见性与交互）。

## 5. 禁止事项

- 不手改 `.runtime` 正式数据，不重写既有商品 ID、订单或权益记录。
- 不把组级课程范围放到每条规格的编辑入口中各自维护。
